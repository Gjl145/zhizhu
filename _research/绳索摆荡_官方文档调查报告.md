## 0. 三个必须先纠正的前提（调查中发现的偏差）

| 你的假设 | 调查结果 |
|---|---|
| Box2D 官方 RopeJoint 有明确推荐参数 | **前提不成立。** Box2D **v3 已彻底移除 RopeJoint**，仅存在于 2.x。v3 官方只有 8 种关节：distance / filter / motor / mouse / prismatic / revolute / weld / wheel。 |

**这个"找不到"本身是最重要的结论**：不存在可以照抄的官方 Unity 摆荡参数表。但下面 Box2D / Jolt / Unreal 提供了**有理论依据的迁移路径**。

## 1. Unity 官方文档（一手）

### 1.1 SpringJoint 类文档
- URL（验证可访问）：`https://docs.unity3d.com/ScriptReference/SpringJoint.html`
- 组件手册：`https://docs.unity3d.com/6000.2/Documentation/Manual/class-SpringJoint.html`

**官方定义（原文）**：

> The spring joint ties together 2 rigid bodies, spring forces will be automatically applied to keep the object at the given distance.
> The Spring attempts to maintain the distance it has when it starts out. So if your joint's start at a rest position where the two rigidbodies are far apart, then the joint will attempt to maintain that distance. The minDistance and maxDistance properties add on top of this implicit distance.

> spring — The spring force used to keep the two objects together.
> damper — The damper force used to dampen the spring force.
> minDistance / maxDistance — The minimum/maximum distance between the bodies **relative to their initial distance**.
> tolerance — The maximum allowed error between the current spring length and the length defined by minDistance and maxDistance.

**⚠️ 关键陷阱（官方原文）**：SpringJoint 的 spring/damper 是**绝对力值**（force per unit distance / damper force），不是频率或比率。而且 rest length 是**初始化时的隐式距离**——`minDistance`/`maxDistance` 是"相对于初始距离"的增量，不是世界空间长度。

**这意味着 SpringJoint 天生不适合做绳索**：绳索需要"硬上限、绝不拉伸"，而 SpringJoint 是"围绕初始距离的双向弹簧"，会振荡、会被拉开。官方手册自己写明 `Damper` 的作用是"prevent the spring from oscillating endlessly"——即官方承认它会振荡。

**官方是否给出推荐数值：没有。** 全文无任何 spring/damper 的建议数值、范围或起始值。

**Mass Scale 官方原文（对你们球体摆荡直接相关）**：
> The scale to apply to the inverted mass and inertia tensor of the Rigidbody, ranging from 0.00001 to infinity. This is useful when the joint connects two Rigidbodies of largely varying mass. **The physics solver produces better results when the connected Rigidbodies have a similar mass.** When your connected Rigidbodies vary in mass, use this property with the Connect Mass Scale property to apply fake masses to make them roughly equal to each other. This produces a high-quality and stable simulation, but reduces the physical behaviour of the Rigidbodies.

这是 Unity 官方对"关节两端质量差异"给出的**唯一明确处理建议**（用 massScale 拉平），但同样**无数值**。

### 1.2 Rigidbody 质量
- URL：`https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rigidbody-mass.html`

> The mass of the rigidbody. **Different Rigidbodies with large differences in mass can make the physics simulation unstable.**

质量组件手册（`class-Rigidbody.html`）：
> Mass is set to 1 by default. As in real life, mass does not affect how quickly an item falls under gravity. To simulate resistance forces that slow down movement, use Drag.
> Linear Damping / Angular Damping — Define the decay rate of a Rigidbody's linear/rotational velocity... Note that you cannot make the GameObject stop rotating just by setting its Angular Damping to infinity.

官方默认：Mass = 1，Contact Offset = 0.01，Max Angular Speed = 50 rad/s，Sleep Threshold 官方在此页**未给数值**。

### 1.3 Physics 项目设置（求解器迭代 —— 对"缓慢下沉"最相关）
- URL：`https://docs.unity3d.com/6000.0/Documentation/Manual/class-PhysicsManager.html`

**官方定义（原文）**：

> **Default Solver Iterations** — Define how many solver processes Unity runs on every physics frame. Solvers are small physics engine tasks which determine a number of physics interactions, such as **the movements of joints** or managing contact between overlapping Rigidbody components. This affects the quality of the solver output, and it is advisable to change the property in case non-default Time.fixedDeltaTime is used, or the configuration is extra demanding. **Typically, it is used to reduce the jitter resulting from joints or contacts.**

> **Default Solver Velocity Iterations** — Set how many velocity processes a solver performs in each physics frame. The more processes the solver performs, the higher the accuracy of the resulting exit velocity after a Rigidbody bounce. **If you experience problems with jointed Rigidbody components or Ragdolls moving too much after collisions, try increasing this value.**

> **Gravity** — ...Gravity is defined in world units per seconds squared.
> **Note: If you increase the gravity, you might need to also increase the Default Solver Iterations value to maintain stable contacts.**

**★ 最高价值的官方发现 —— Solver Type（直接针对绳索过伸）**：
> **Temporal Gauss Seidel**: This solver offers a better convergence and a better handling of high-mass ratios, **minimizes energy introduced when correcting penetrations and improves the resistance of joints to overstretch.** It usually helps when you experience some erratic behavior during simulation with the default solver.
> （默认是 Projected Gauss Seidel）

**这是全网唯一一份官方明确写出"抗关节过伸"（resistance of joints to overstretch）的 Unity 文档。** 摆荡绳索的过伸问题，官方给出的对策就是切 Temporal Gauss Seidel。

**★ Bounce Threshold（官方明确的反抖动指引）**：
> Set a velocity value. If two colliding objects have a relative velocity below this value, they do not bounce off each other. **This value also reduces jitter, so it is not recommended to set it to a very low value.**

> **Default Contact Offset** — ...The value must be positive, and **if set too close to zero, it can cause jitter. This is set to 0.01 by default.**

**官方是否给出推荐数值：** 仅 **Contact Offset = 0.01**、**Max Angular Speed = 50**、**Scratch Buffer Chunk Count = 4**、**Inter-Collision Distance = 0.1 / Stiffness = 0.2**（Cloth 专用）有明确数值。**Default Solver Iterations / Velocity Iterations / Spring / Damper 一律没有推荐数值。**

### 1.4 Fixed Timestep 与 Physics.Simulate
- `https://docs.unity3d.com/6000.0/Documentation/Manual/class-TimeManager.html`
- `https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Time-fixedDeltaTime.html`
- `https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Physics.Simulate.html`

> **Fixed Timestep** — A frame rate independent interval that dictates when physics calculations and FixedUpdate events are performed.
> **Maximum Allowed Timestep** — ...caps the worst case scenario when frame rate is low. Physics calculations and FixedUpdate events will not be performed for longer time than specified.

> **Time.fixedDeltaTime** — The interval in seconds of in-game time at which physics and other fixed frame rate updates (like MonoBehaviour's FixedUpdate) are performed.

> **Physics.Simulate** — Call this to simulate physics manually **when the simulation mode is set to Script**. Simulation includes all the stages of collision detection, **rigidbody and joints integration**... Calling Physics.Simulate does not cause FixedUpdate to be called.

**官方默认 fixedDeltaTime = 0.02s（50Hz）**（此数值来自 Project Settings 默认值，官方 API 页本身未复述）。

**★ 重要发现：Unity 内置 PhysX 没有子步进（substep）设置。** 我逐项检查了 Physics 设置页的全部 tab，**不存在任何 substep 选项**。想手动多步推进只能：Simulation Mode = Script + 在自己的循环里反复调 `Physics.Simulate(fixedDt)`。

**★ 官方对"改了 fixedDeltaTime 要怎么办"给了指引**（见 1.3）："it is advisable to change the property [Default Solver Iterations] in case non-default Time.fixedDeltaTime is used"。这是官方承认 fixedTimestep 与迭代次数必须联动。

### 1.5 Rigidbody.solverIterations（逐物体覆盖）
- `https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rigidbody-solverIterations.html`

> The solverIterations determines how accurately **Rigidbody joints** and collision contacts are resolved. Overrides Physics.defaultSolverIterations. Must be positive.
> **If you are having trouble with connected Rigidbodies oscillating and behaving erratically setting a higher solver iteration count may improve their stability (but is slower).**

> **solverVelocityIterations** — ...If you are experiencing issues with jointed Rigidbodies or Ragdolls **moving too much** after collisions you can try to increase this value.

**官方明确承认关节会"移动过多/振荡"，但不给数值。**

### 1.6 Unity Physics (DOTS) —— 官方唯一有"子步进"的官方文档 ★★★
- URL：`https://docs.unity3d.com/Packages/com.unity.physics@6.5/manual/component-step.html`

**官方定义（原文）**：
> **Substep Count** — Specifies the number of substep iterations the physics system performs. The duration of a substep equals the physics frame time divided by the number of substep iterations. **Higher values mean smaller timesteps per frame. This can improve stability up to a point where the timestep becomes so small that computational numerical errors arise.** Higher values can provide more accuracy and stability when solving constraints, but can reduce simulation performance. In each substep, the solver runs as many iterations as defined by Solver Iteration Count to compute the joint and contact forces.

> **Solver Iteration Count** — Specifies the number of solver iterations the physics system performs to correct contact penetrations and **joint errors**. Higher values provide more accuracy and stability, but can reduce simulation performance.

**这是 Unity 官方对"离散步长 ↔ 稳定性"最明确、最有理论依据的表述**，且给出了**权衡的双向边界**（"up to a point where the timestep becomes so small that computational numerical errors arise"）——子步不是越多越好。**注意：此页属于 com.unity.physics（DOTS/Entities 包），不适用于内置 PhysX 的 GameObject。**

## 2. Box2D（一手，最高参考价值）

### 2.1 ⚠️ RopeJoint 在 v3 已被移除（一手证据）
- 迁移指南：`https://box2d.org/documentation/md_migration.html`（验证可访问）
  > gear and pulley joint removed (temporarily)
  > The friction joint has been removed since it is a subset of the motor joint. The pulley and gear joints have been removed. I'm not satisfied with how they work in 2.4 and plan to implement improved versions in the future.
- v3 官方关节列表：`https://box2d.org/documentation/` → Joint 章节仅 distance / filter / motor / mouse / prismatic / revolute / weld / wheel。**无 rope。**
- 2.4.1 旧版文档入口（验证可访问）：`https://box2d.org/doc_version_2_4/`（doxygen 确认版本号 **2.4.1**）
- 2.4 官方源码（一手）：`https://raw.githubusercontent.com/erincatto/box2d/v2.4.0/include/box2d/b2_rope_joint.h`

**注意**：官方 migration 文档**没有一句提到 rope 被移除**——只在第三方绑定（forge2d）的 release notes 里明确写了 "Gear, pulley, rope, friction, and constant-volume joints do not exist in Box2D v3"。但 v3 官方文档与头文件目录中确无 rope，二者一致。

### 2.2 ★★★ RopeJoint 官方语义（2.4.1，一手源码原文）

```c
/// Rope joint definition. This requires two body anchor points and
/// a maximum lengths.
/// Note: by default the connected objects will not collide.
/// see collideConnected in b2JointDef.
struct b2RopeJointDef : public b2JointDef {
    b2Vec2 localAnchorA;   // The local anchor point relative to bodyA's origin.
    b2Vec2 localAnchorB;   // The local anchor point relative to bodyB's origin.
    /// The maximum length of the rope.
    /// Warning: this must be larger than b2_linearSlop or
    /// the joint will have no effect.
    float maxLength;
};
```

> **A rope joint enforces a maximum distance between two points on two bodies. It has no other effect.**
> **Warning: if you attempt to change the maximum length during the simulation you will get some non-physical behavior. A model that would allow you to dynamically modify the length would have some sponginess, so I chose not to implement it that way. See b2DistanceJoint if you want to dynamically control length.**

**三条极其重要的官方结论**：

1. **RopeJoint 是单向约束**（"enforces a maximum distance... It has no other effect"）——距离小于 maxLength 时**完全不施力**。这正是绳索"只拉不推"的正确物理，也是它不会像 SpringJoint 那样振荡的原因。
2. **maxLength 必须 > `b2_linearSlop`，否则关节完全无效**。`b2_linearSlop = 0.005f`（5mm），官方注释见 `b2_settings.h`。→ **这就是"绳索缓慢下沉"的第一机制**。
3. **官方禁止在仿真中途改 maxLength**，明确说会得到"non-physical behavior"和"sponginess"。收线/放线必须靠 motor（见 2.4）。

**★ 官方是否给出推荐数值？RopeJoint 本身没有给 maxLength 的推荐值**（它由使用场景决定）。**但官方给了两条硬约束数值**：`b2_linearSlop = 0.005f`、`b2_maxLinearCorrection = 0.2f`（见 2.5）。

### 2.3 ★ v3 DistanceJoint：minLength / maxLength 的官方语义（一手）
- URL：`https://box2d.org/documentation/group__distance__joint.html`（验证可访问）
- 文档源码：`https://raw.githubusercontent.com/erincatto/box2d/main/docs/simulation.md`

**结构体官方定义（原文）**：
> **Distance joint definition.** This requires defining an anchor point on both bodies and the non-zero distance of the distance joint. The definition uses local anchor points so that the initial configuration can violate the constraint slightly. This helps when saving and loading a game.
>
> - `length` — The rest length of this joint. **Clamped to a stable minimum value.**
> - `minLength` — Minimum length. **Clamped to a stable minimum value.**
> - `maxLength` — **Maximum length. Must be greater than or equal to the minimum length.**
> - `enableSpring` — Enable the distance constraint to behave like a spring. **If false then the distance joint will be rigid, overriding the limit and motor.**
> - `hertz` — The spring linear stiffness Hertz, cycles per second.
> - `dampingRatio` — The spring linear damping ratio, non-dimensional.
> - `enableLimit` — Enable/disable the joint limit.

**关键函数官方说明（原文）**：
> **b2DistanceJoint_EnableLimit** — Enable joint limit. **The limit only works if the joint spring is enabled. Otherwise the joint is rigid and the limit has no effect.**

**★ 这是修正"绳索下沉"的核心机制**：官方明确指出 **limit（minLength/maxLength）只有在 `enableSpring = true` 时才生效**。`enableSpring = false` 是刚性约束、limit 被忽略。同时 `length` 和 `minLength` 都被 "Clamped to a stable minimum value"——即**存在一个不可消除的最小间隙，绳索永远可能被拉长这么多**。这个 stable minimum 就是 Box2D 版的 `linearSlop` 角色。

### 2.4 ★★★ Box2D 官方唯一给出的"推荐参数"（原文逐字）

出自 `docs/simulation.md`（Box2D 官方手册源文件）：

> The hertz is the frequency of a harmonic oscillator (like a guitar string). **Typically the frequency should be less than a half the frequency of the time step. So if you are using a 60Hz time step, the frequency of the distance joint should be less than 30Hz. The reason is related to the Nyquist frequency.**
>
> **The damping ratio controls how fast the oscillations dissipate. A damping ratio of one is critical damping and prevents oscillation.**
>
> It is also possible to define a minimum and maximum length for the distance joint. You can even motorize the distance joint to adjust its length dynamically.

**官方代码示例中的数值**（原文）：
```c
jointDef.enableSpring = true;
jointDef.hertz = 2.0f;
jointDef.dampingRatio = 0.5f;
```

**→ 这是全套调查中最硬的官方推荐数值：hertz = 2.0，dampingRatio = 0.5（示例值），且硬约束 `hertz < 时间步频率 / 2`（Nyquist）。** dampingRatio = 1.0 = 临界阻尼、彻底不振荡。

**★ 官方推荐时间步与子步数（原文）**：
> ...you should use a fixed time step. By using a larger time step you can improve performance in low frame rate scenarios. **But generally you should use a time steps 1/30 seconds (30Hz) or smaller. A time step of 1/60 seconds (60Hz) will usually deliver a high quality simulation.**
>
> The sub-step count is used to increase accuracy. By sub-stepping the solver divides up time into small increments and the bodies move by a small amount. This allows joints and contacts to respond with finer detail. **The recommended sub-step count is 4. However, increasing the sub-step count may improve accuracy. For example, long joint chains will stretch less with more sub-steps.**
>
> The scissor lift sample shown here works better with more sub-steps and is configured to use 8 sub-steps. **With a primary time step of 1/60 seconds, the scissor lift is taking sub-steps at 480Hz!**

**★★ "long joint chains will stretch less with more sub-steps" —— 这句是 Box2D 官方对"绳索链被拉长/下沉"的直接官方解法与官方理由。** 子步进 = 把一步切成 N 个更小的步，让长链约束有更多次修正机会。480Hz 有效子步频率是个官方给出的实测量级参考。

**★ 关于力的施加（子步进的重要副作用，官方原文）**：
> **Caution: Since Box2D uses sub-stepping, you should not apply a steady impulse for several frames. Instead you should apply a force which Box2D will spread out evenly across the sub-steps, resulting in smoother movement.**
>
> With a sub-stepping solver you need to think differently about how you interact with bodies. **Externally applied impulses or velocity adjustments no longer exist after the first sub-step. So if you try to control the movement of a body by setting the velocity every time step then you may get unexpected results. You will get more predictable results by applying a force and/or torque.**

**★★ 这一条对 Unity 摆荡极其重要**：官方明确说子步进下**"每帧设 velocity"会得到非预期结果**，应该用 force。这意味着做摆荡牵引/加速时，用 `AddForce` 而非直接写 `velocity` 或 `linearVelocity`，在多子步下才稳定可预测。Unity 内置 PhysX 没有子步，但如果你们自己手动多步模拟（Simulation Mode=Script + 多次 Physics.Simulate），这条同样适用。

**★ 官方禁止给约束施加速度**：
> If you want full control over the movement of a body, considering setting the body type to `b2_kinematicBody`.

**→ 摆荡的锚点/挂点如果需要精确控制，官方推荐做法是设为 kinematic body（Unity 对应 `isKinematic = true`），而不是每帧改 transform。**

### 2.5 ★★★ 绳索下沉的精确机制（一手源码，`b2_rope_joint.cpp` v2.4.0）

```c
bool b2RopeJoint::SolvePositionConstraints(const b2SolverData& data)
{
    ...
    float C = m_length - m_maxLength;
    C = b2Clamp(C, 0.0f, b2_maxLinearCorrection);   // ①
    float impulse = -m_mass * C;
    ...
    return m_length - m_maxLength < b2_linearSlop;      // ②
}
```
相关官方常量（`b2_settings.h`，v2.4.0）：
```c
/// A small length used as a collision and constraint tolerance. Usually it is
/// chosen to be numerically significant, but visually insignificant.
#define b2_linearSlop          0.005f      // 5mm
/// The maximum linear position correction used when solving constraints. This helps to
/// prevent overshoot.
#define b2_maxLinearCorrection 0.2f
#define b2_baumgarte           0.2f
```

**这就是"绳索缓慢下沉"的完整、官方、可解释的成因（三个叠加的容差）**：

1. **求解器提前收敛退出（②）**：一旦剩余超长量 < `b2_linearSlop = 5mm`，求解器**直接返回 true 停止修正**。绳索静垂后每帧都会被允许保留最多 5mm 的超长。**这是设计上的有意容差，不是 bug。**
2. **单帧修正量上限（①）**：每帧最多修正 `b2_maxLinearCorrection = 0.2m`，超出部分留到下一帧——长链误差收敛慢。
3. **积分层容差**：重力每步持续把绳索往下拉，位置层每步只补回 5mm 以内的容差，净效果就是**缓慢下沉并稳定在一个"下垂 5mm×链长"的新平衡点**。

**★ 官方给出的正解（按优先级）**：
- 加子步（`subStepCount` 4→8+，官方："long joint chains will stretch less with more sub-steps"）
- 减小时间步（官方：1/30s 或更小，1/60s 为高质量）
- 理解并接受 `linearSlop` 量级的容差是**物理上不可避免**的，不必追求零下垂

## 3. 其他引擎（一手）

### 3.1 Unreal Engine 物理子步进
- URL（验证可访问，英文原文）：`https://dev.epicgames.com/documentation/unreal-engine/physics-sub-stepping?application_version=4.27`
- 中文版：`https://dev.epicgames.com/documentation/zh-cn/unreal-engine/physics-sub-stepping-in-unreal-engine?application_version=5.3`

**官方定义（原文）**：
> Unreal Engine 4 uses a **variable frame rate**. While this is good for hardware scalability, it creates a challenge for the physics engine, **which works best with small fixed time steps.** Sub-stepping takes the total frame time and divides it into sub-steps. The physics simulation is then ticked multiple times per frame. **The smaller the max sub-step time the more stable your simulation will be, but at a greater CPU cost.**

> **Max Substep Delta Time** — This is the maximum time, in seconds a sub-step is allowed to take. So, if a full step takes .05 seconds, and Max Substep Delta Time is set to .025, the full step will be split into 2 sub-steps. Now, if the full step were to take a substantial amount of time, say 2 full seconds, then the step will be evenly split based on the value in Max Substeps, and not 80 (2.0/0.025=80) sub-steps. It is worth noting that Max Physics Delta Time limits how long a physics step is permitted to take.
>
> **Max Substeps** — The maximum number of sub-steps a full step is permitted to be broken into.

> **Sub-stepping will significantly improve the quality of complex physics assets, such as those used for rag doll.**

**★ 官方给出的参数示例值：Max Substep Delta Time = 0.025s**（当整步 0.05s 时拆成 2 子步）。**官方没有推荐绝对数值，但给了机制示例。** ⚠️ 官方标注该功能 "still a work in progress"、UE4 时代"not supported on mobile devices"。

**★ 官方警告子步进会破坏碰撞回调语义（对游戏逻辑有实际影响）**：
> we delay the collision callbacks until the final sub-step is done. **This means that you can get several callbacks for the same collision.** For example, if A collides with B and bounces off, you may get a callback for A and B overlapping AND a callback for A and B no longer overlapping in the same frame.

### 3.2 Jolt Physics（一手，参数最全）
- `https://jrouwe.github.io/JoltPhysicsDocs/5.2.0/class_distance_constraint_settings.html`（验证可访问）
- `https://jrouwe.github.io/JoltPhysicsDocs/3.0.1/class_distance_constraint_settings.html`
- 官方源码：`https://raw.githubusercontent.com/jrouwe/JoltPhysics/master/Jolt/Physics/PhysicsSettings.h`

**Jolt DistanceConstraintSettings 官方定义（原文）**：
> - `mMinDistance` / `mMaxDistance` — Ability to override the distance range at which the two points are kept apart. **If the value is negative, it will be replaced by the distance between mPoint1 and mPoint2.**
> - `mLimitsSpringSettings` — When enabled, this makes the limits soft. **When the constraint exceeds the limits, a spring force will pull it back.**
> - `mFrequency` (v3.0.1) — **If mFrequency > 0 the constraint will be soft and mFrequency specifies the oscillation frequency in Hz and mDamping the damping ratio (0 = no damping, 1 = critical damping). If mFrequency <= 0, mDamping is ignored and the distance constraint will have hard limits (as hard as the time step / the number of velocity / position solver steps allows).**

**★★★ Jolt 官方对"显式欧拉造成能量损失"的直白承认（这是"绳索下沉"最有理论依据的官方陈述之一，v3.0.1 原文逐字）**：
> **Note that if you set mDamping = 0, you will not get an infinite oscillation. Because we integrate physics using an explicit Euler scheme, there is always energy loss. This is done to keep the simulation from exploding, because with a damping of 0 and even the slightest rounding error, the oscillation could become bigger and bigger until the simluation explodes.**

**→ 官方承认：显式欧拉积分本身就有能量损失（这是数值稳定性的刻意设计，不是缺陷）。** 这从第一性原理解释了为什么摆荡会"缓慢下沉"：不是 bug，是显式积分的固有耗散 + 约束容差的必然结果。

**Jolt 官方 PhysicsSettings 默认值（一手源码，`PhysicsSettings.h`）**：
```c
/// Baumgarte stabilization factor (how much of the position error to 'fix' in 1 update)
/// (unit: dimensionless, 0 = nothing, 1 = 100%)
float mBaumgarte = 0.2f;

/// How much bodies are allowed to sink into each other (unit: meters)
float mPenetrationSlop = 0.02f;

/// Number of solver velocity iterations to run
/// Note that this needs to be >= 2 in order for friction to work
uint mNumVelocitySteps = 10;

/// Number of solver position iterations to run
uint mNumPositionSteps = 2;

/// Minimal velocity needed before a collision can be elastic. (unit: m)
float mMinVelocityForRestitution = 1.0f;

/// Time before object is allowed to go to sleep (unit: seconds)
float mTimeBeforeSleep = 0.5f;

/// Radius around objects inside which speculative contact points will be detected.
float mSpeculativeContactDistance = 0.02f;
```
**官方默认：velocity 迭代 10 / position 迭代 2。** 对比 Box2D 的 4 子步 × Soft Step，Jolt 用"更多速度迭代"达到稳定——两者思路不同，但都指向"同一位移预算内多迭代几次"。

**★ Jolt 的 substep 替代方案（一手 API）**：`SetNumVelocityStepsOverride` / `SetNumPositionStepsOverride` — **可对单个约束单独提高迭代数**（"The number of iterations to use is the max of all contacts and constraints in the island"）。这是"只给绳索加迭代、不全局加"的官方做法，对球体摆荡（只有一个玩家绳索）性价比极高。Unity 无同等 API，只能用全局 `Rigidbody.solverIterations`（Unity 恰好支持逐刚体覆盖，某种程度上等价）。

## 5. 结论与可执行建议

### 5.1 三个问题的直接回答

**Q1：官方推荐用什么组件实现？**
- **Unity：无任何官方推荐。** 官方只提供 SpringJoint（双向弹簧，会振荡，非绳索语义）。
- 从语义正确性看，SpringJoint **不适合**做绳索：它是"围绕初始距离的双向弹簧"，需要靠 damper 抑制振荡。绳索的正确语义是 Box2D RopeJoint 那样的**单向硬上限**（"enforces a maximum distance... It has no other effect"）。
- 实践上的等价方案：SpringJoint + `minDistance = 0` + 把 rest length 设为绳长 + 极高 spring；或 ConfigurableJoint 的 Linear Limit（`limit = 0, limitForce = ∞`）实现单向约束。**这三种都是社区做法，不是官方推荐。**

**Q2：官方有没有给推荐参数？**
| 参数 | 官方推荐值 | 出处 |
|---|---|---|
| SpringJoint spring / damper | **无** | Unity 从未给出 |
| SpringJoint massScale | 仅原则无数值（"make them roughly equal"） | Unity Spring Joint 手册 |
| Default Solver Iterations | **无** | Unity Physics 设置 |
| Unity substep | **不存在此设置** | Unity Physics 设置（内置 PhysX 无子步） |
| Unity DOTS Substep Count | **无数值**，但有明确的双向边界说明 | com.unity.physics Physics Step |
| 接触容差 | Contact Offset = **0.01** | Unity Physics 设置 |
| 抗关节过伸 | 切 **Temporal Gauss Seidel** | Unity Physics 设置 Solver Type |
| **DistanceJoint hertz** | **2.0**（示例值）+ 硬约束 **< 时间步频率/2**（Nyquist） | Box2D 官方 simulation.md |
| **DistanceJoint dampingRatio** | **0.5**（示例）；**1.0 = 临界阻尼、不振荡** | Box2D 官方 simulation.md |
| **时间步** | **1/30s 或更小；1/60s 为高质量** | Box2D 官方 simulation.md |
| **子步数** | **推荐 4**；长链"8 sub-steps @ 1/60s = 480Hz" | Box2D 官方 simulation.md |
| **绳索最小容差** | **maxLength 必须 > 0.005m** | Box2D b2_rope_joint.h + b2_settings.h |
| UE Max Substep Delta Time | 示例 0.025s（机制示例，非推荐值） | UE 4.27 文档 |
| Jolt 迭代 | velocity **10** / position **2** / Baumgarte **0.2** | Jolt PhysicsSettings.h |
| 摆荡手感 / 蛛丝参数 | **完全不存在** | — |

**Q3：离散步进问题官方怎么解？**
四条官方一致的手段（全部有一手出处）：
1. **加子步** — Box2D："long joint chains will stretch less with more sub-steps"，推荐 4，长链用 8+。UE：整帧拆子步。Unity DOTS：Substep Count。**Unity 内置 PhysX 没有 → 需自行用 Simulation Mode=Script + 多次 Physics.Simulate 模拟。**
2. **减小时间步** — Box2D：1/30s 或更小，1/60s 高质量。Unity：改 `Time.fixedDeltaTime`，**但 Unity 官方要求同步提高 Default Solver Iterations**。
3. **提高位置/速度迭代** — Unity：`Default Solver Iterations` / `Rigidbody.solverIterations`（可逐刚体覆盖）；Jolt：默认 10/2，可按约束覆盖。
4. **换求解器 / 换尺度** — Unity：Temporal Gauss Seidel "improves the resistance of joints to overstretch"；Box2D/Jolt：hertz 受 Nyquist 约束，dampingRatio = 1 临界阻尼。

### 5.2 关于"绳索摆荡会缓慢下沉"——机理结论（有官方依据）

**这不是 bug，是三处官方设计的容差叠加，理论上无法也不必消除到零：**

1. **显式积分固有耗散**（Jolt 官方原文）："we integrate physics using an explicit Euler scheme, there is always energy loss."
2. **约束容差 slop**（Box2D 官方源码）：求解器在剩余误差 < `b2_linearSlop = 5mm` 时**主动停止修正**并返回成功。绳索静垂后每帧可保留 5mm 超长。
3. **单帧修正上限**（Box2D 官方源码）：每帧最多修正 `b2_maxLinearCorrection = 0.2m`，长链误差收敛慢。

**可执行的对策（按官方依据强度排序）**：

| 优先级 | 措施 | 官方依据 |
|---|---|---|
| 1 | Physics Settings → **Solver Type 改 Temporal Gauss Seidel** | Unity 官方：improves the resistance of joints to overstretch |
| 2 | 降低 `Time.fixedDeltaTime`（如 0.02 → 0.01）+ **同步提高 Default Solver Iterations** | Unity 官方两处交叉指引；Box2D 1/30s 或更小 |
| 3 | 只给玩家绳索的 Rigidbody 提 `solverIterations` / `solverVelocityIterations` | Unity 官方 API 支持逐刚体覆盖；Jolt 同样支持按约束覆盖 |
| 4 | 若可接受 Simulation Mode=Script，**手动多步 Physics.Simulate 模拟子步** | Box2D/UE 官方机制；Unity DOTS 官方 Substep Count 语义 |
| 5 | 用 `massScale` / `connectedMassScale` 拉平玩家球与锚点的质量 | Unity Spring Joint 手册："produces a high-quality and stable simulation" |
| 6 | **不要用 `spring` 硬撑绳长**；改用单向约束（ConfigurableJoint Linear Limit 或 spring+minDistance=0） | Box2D：单向语义 "has no other effect"；SpringJoint 是双向弹簧会振荡 |
| 7 | 牵引/加速改用 `AddForce` 而非每帧写 velocity | Box2D 官方 Caution：子步下 "velocity adjustments no longer exist after the first sub-step" |
| 8 | 挂点/锚点用 `isKinematic = true` 而非每帧改 transform | Box2D 官方："considering setting the body type to b2_kinematicBody" |
| 9 | 若弹簧化阻尼：dampingRatio 参照 **1.0 = 临界阻尼**；hertz 必须 **< 步频/2** | Box2D 官方 simulation.md |

### 5.3 明确"找不到"的项

- Unity 官方**没有**任何 rope / chain / swing / grappling 的实现指南或教程页（已核查 Joints 全目录、Physics 设置、Component Reference）。
- Unity 官方**没有**给 SpringJoint spring/damper/minDistance/maxDistance/tolerance 任何推荐数值或范围。
- Unity 官方**没有**给 Solver Iterations 推荐数值。
- PhysX / NVIDIA 官方文档中**未找到** rope/swing 专项指引。
- Havok 官方约束求解文档：本次未取得可验证的官方页面，**不作任何声明**。
- 悬摆/摆的"半隐式欧拉 vs 显式欧拉稳定性"通用理论，本次调查中被 Jolt 官方那段 explicit Euler 说明实质覆盖；未找到引擎官方对"半隐式欧拉用于摆"的具体推荐，故不引用二手理论文章。
