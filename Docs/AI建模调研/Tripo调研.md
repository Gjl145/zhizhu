## 一、视频内容（抽帧 + 转写核实）

这是 **Tripo Studio** 的功能演示广告，不是教程。核心是三个对比：

| 传统做法 | Tripo 做法 |
|---|---|
| 给三明治加生菜 → 手动一片片建模 | 导入图片 → 直接生成带拓扑的 3D 模型 |
| 给瓶子加纹理 → 贴标签 | 加「旋转修改器」→ 一转就有螺旋纹 |
| 手动加表面细分 | 导入图片 → 直接生成 → 无需调整 |

画面里能看到的能力（**这是关键，比转写可靠**）：

1. **从参考图生成分层模型** —— 画面里三明治的生菜 / 面包 / 番茄是**分离的对象**，
   可单独选中、各自带完整网格。不是一整块 mesh。
2. **拓扑是干净的四边面** —— 瓶子模型上能看到规整的 quad 网格 + 蓝色选中描边，
   能进 Blender 直接用「旋转」「布料」「缩放」等修改器。
3. **接 Blender 修改器** —— 演示里给生菜加「布料」物理模拟（勾选内部弹簧、自碰撞），
   给瓶子加「旋转」，给模型加「表面细分」。**这是本视频最重要的信息。**
4. **分类明确** —— 界面底部可见 `Character / Vehicle / Animal / Architecture` 四个入口。

★ **对本项目的意义**：它证明「AI 生成的模型是可以继续编辑的」，
不是只能当静态摆件的「死网格」。这正好对上我们白盒建模的痛点。

## 二、Tripo 是什么（官方资料核实）

| 项 | 内容 | 出处 |
|---|---|---|
| 底层模型 | Tripo 3.0，**200 亿参数**，10 亿体素分辨率 | tripo3d.ai/blog |
| 训练数据 | 4000 万模型库 | 同上 |
| API 用户 | 4 万+开发者、700 家企业客户 | 同上 |
| API 一致性 | **网页版与API 效果一致**（同一个模型驱动）| 同上 |
| 支持面| Blender / Unity / Unreal / Maya / 3ds Max / Godot / Cocos / ZBrush 插件 | developers.tripo3d.ai/docs/plugins |

### 核心端点

| 端点 | 用途 | 我们的场景 |
|---|---|---|
| `text_to_model` | 文本生成 3D | 快速出草稿 |
| `image_to_model` | **图片生成 3D** | ★ 首选 —— 可用参考图控制造型 |
| multiview | 多视图生成 | 同一物体的多角度一致性 |
| texture | 给已有模型重新贴图 | 我们已有白盒，补贴图 |
| **segmentation** | **把模型拆成部件** | ★ 与视频里「生菜/面包分离」对应 |
| **retopology** | 重拓扑（低面数） | ★ 实时游戏必需 |
| **rigging** | 自动绑骨 | 后续 NPC |
| PBR 生成 | 输出贴图模型 | 材质 |

### 输出格式与Unity 导入

- 官方Unity 插件：ZIP 解压后把含 `package.json` 的目录放进 `Packages/`，
  菜单 `Tools > Tripo API Unity`
- 官方 **Unity Bridge**（DCC Bridge）：Studio 里 `Export → Send to Unity`，
  **自动检测渲染管线**（Standard / URP / HDRP）——
  ★ 这能避免我们之前遇到的「紫色材质」问题
- 格式选择（官方博客明确）：
  - **FBX** → 带绑骨的角色与动画
  - **GLB** → ★ **静态道具与场景物件**
  - OBJ → 静态几何，不带绑定

## 五、对 zhizhu 项目的适配性分析

### ★ 我们的坐标系约定是X=左右 Y=前后 Z=高度（非Unity Y-up）

这是最大的技术风险。AI 生成的模型都是 **Y-up**（Blender/FBX 惯例），
而本项目 Z-up。导入后需要旋转 **−90° 或 +90°**。
`HouseBlockout` 的做法是所有物件都由脚本定位，我们仍需保证：

1. **模型原点（pivot）** —— 必须落在物体底部中心，
   否则摆放时会陷进地板。导出时用 `pivot_to_center_bottom` 参数。
2. **尺度** —— Tripo 输出是「真实尺寸」，
   我们的 1 米 = 5 格，所以 4.5米的房间 = 22.5 格，
   一个 0.8 米的马桶 = 4 格。**这个换算必须应用到每个导入模型上。**
3. **法线** —— Unity 用 **OpenGL（Y+）法线**，与 Blender 一致。
   若模型来自 DirectX 工具，要开 `Flip Green Channel`。

### 能用 AI 替换的部分（我们白盒做的）

| 白盒现状 | AI 能替代吗 | 判断 |
|---|---|---|
| 房间墙体/楼板（薄板拼的）| **不该替代** | ★ 结构要精确，靠规范算的尺寸比AI 可靠 |
| 家具（床、灶台、马桶）| **能** | ★ 用户明确说「先把基本框架搭出来」，家具后置 |
| 门窗（墙垛+门楣拼的）| 部分能 | AI 生成的门框能带门洞，但尺寸要改 |
| 楼板洞口 | 不该替代 | 纯几何计算 |
| **锚点（可钩点）** | **不该替代** | ★ 我们需要「可抓」的判定依据，不是好看的球 |

★ **核心结论：AI 替代「装饰层」，不替代「结构层」。**
结构层（墙/楼板/楼梯/洞口）必须按国标算，因为关卡要能通关、
要有确定的碰撞体积。装饰层（家具/装饰/杂物）用 AI 批量生成，
这正是用户的「风景填充」诉求。

### 一个必须先解决的前置问题

我们上一轮才刚给球加了**墙体碰撞**（`SolveWallCollision`，SphereCast）。
导入的 AI 模型**必须带 Collider**，否则球会直接穿过去——
这正是我们刚修好的问题不能被新资产破坏。

好消息：Unity 导入 FBX/GLB 时勾选 `Generate Colliders` 即可自动生成。
但要注意 **MeshCollider 是凸包近似**，凹形道具（椅子中间的空档）
会「填平」。解法是在 Unity 里挂 `MeshCollider` 时取消 convex，
或用多个凸包近似（PhysicMaterial 的 `MeshColliderCookingOptions`）。

## 六、第三方实测数据（2026 年，不是厂商宣传）

这是本次调研最有价值的部分—— **找到了独立评测**，避免了只看厂商宣传。

### SimInsights 40 次生产环境试用（2025）

> 原文结论：「今天的 AI 3D 生成器能在**有经验的美术师手里**加速
> 背景道具和 LOD，但**对主角资产、复杂几何体、角色、环境，
> 或任何带可读文字的东西都不可靠**。」

| 工具 | 评测结果 |
|---|---|
| **Tripo** | **工作流与可编辑性最好**，但容易有破洞与破面几何，需手工修 |
| Meshy | 多数输出因几何破损、贴图弱而被拒 |
| Rodin | 贴图质量最好，但网格更重、形状错误更频繁 |

行业统计：**约 10 次生成里只有 1 次**能不经大幅返工直接使用。

### 已知缺陷清单（多来源交叉验证）

| 缺陷 | 影响到我们吗 |
|---|---|
| 非封闭网格、有孔洞 | ★ **孔洞会让球从缝里漏过去**（我们刚修好墙体碰撞）|
| 壁太薄 | 不影响游戏 |
| 内部漂浮几何 | 视觉噪点 |
| UV 错乱、贴图撕裂 | ★ 重拓扑后必然发生，贴图要重烘 |
| **左右不对称** | 中式家具（尤其）会明显 |
| **部件焊死成一团** | ★ 视频里三明治能分离部件，但实测说「常常焊在一起」|
| 面数过高（有箱子50000 面） | ★ 必须 Smart Mesh 重拓扑 |
| 可读文字是乱码 | 生成带字的招牌/书刊会出现乱码 |

### 中式家具的还原度（我们最关心的）

**没有找到任何针对中式家具的评测。** Tripo 官方测评报告里
「家具」类只说「形态还原不错、材质纹理精准」，配图全是**现代家具**
（沙发、抱枕、柜子雕花）。

结合官方自己承认「AI 依赖训练数据质量，并不具备真正的物理理解能力」，
可以合理推断：
- 现代款家具（三明治、塑料瓶这类）→ 训练数据充足，还原度高
- **中式家具（明清样式、榫卯、中式床、灶台）→ 训练数据稀疏，
  很可能生成「带中式元素的西式家具」或直接给出现代款**

★ 这是**必须实测的第一件事**，不要先假定能用。

### 尺寸精度（e-architect 文章的警告）

> Autodesk 设计团队 2024 年就指出：AI 生成器**无法产出尺寸精确的模型**，
> 且这一差距到 2026 年中仍未缩小。**把每个输出都当草图看。**

文章还专门点出一个最常被跳过的检查：

> 「你导入一把 50 米高的椅子，走道都建好了才发现——
>  **AI 网格的落点是任意的真实世界尺寸。**」

★ 与我们的 1 米 = 5 格换算是直接冲突的，必须逐个核对。

## 七、修正后的判断

### 能替代什么（降低预期）

| 用途 | 可行性 | 依据 |
|---|---|---|
| **背景杂物**（堆在角落的箱子、瓶子）| ★★★ 最好 | SimInsights 明确认可 |
| **LOD 备用模型** | ★★★ | 同上 |
| 概念草稿 | ★★☆ | 本来就该快 |
| 装饰层家具 | ★★☆ | 需清几何 |
| **主要家具**（床/灶台/马桶）| ★☆☆ | 「10 个里 1 个能用」|
| **结构**（墙/楼板/楼梯）| ☆☆☆ | **绝不可替代** |

### 定价的现实感

「100 个背景道具 ≈ $80」这个数字成立的前提是**背景道具**。
若是我们要的**中式主要家具**，按「10 个里 1 个可用」算，
100 个可用模型 = 生成 1000 次 ≈ **$800+**，且每个还要手工修几何。

★ 与手工建模对比：一个中式床的美术工时通常在数小时到一天，
按外包价 $30-80/小时算，「手工反而更便宜」是真实可能。

### ★ 修正后的结论

**Tripo 值得用，但用途要收窄到「背景杂物」这一类。**

- ✅ **现在就能用**：填充房间里的杂物（小物件、箱子、瓶子、书本）——
  这些占视觉密度，但没人会仔细看几何
- ⚠️ **要验证再用**：主要家具 —— 先测中式还原度
- ❌ **不用**：结构层 —— 按国标算的尺寸比 AI 可靠，且关卡要能通关

★ 与用户「风景填充」的诉求其实吻合：
**风景填充 ≈ 背景杂物，不是主体建筑。**
这个定位正好避开了 AI 最弱的地方。

## 八、建议的落地路径

### 阶段 0：先验证（免费额度内做完，$0）

注册拿 2000 API credits（约 $20），生成 5 个东西验证关键假设：

| # | 生成什么 | 验证什么 |
|---|---|---|
| 1 | 「中式实木架子床，榫卯结构，明代风格」 | ★ **中式还原度** —— 最大的未知 |
| 2 | 「Chinese kitchen wok stove, tiled wall」 | 中式厨房设备 |
| 3 | 「wooden crate, weathered」 | 背景杂物（预期最可靠）|
| 4 | 「ceramic toilet bowl」 | 常规卫浴（对比中式）|
| 5 | 中式房间参考图 → `image_to_model` | 图片输入能否锚定结构 |

导出全部用 **GLB**，丢进 Unity 逐个查：
- [ ] 尺度（对照 1 米 = 5 格；**官方不保证尺寸**，必须自己量）
- [ ] pivot 在不在底部中心（否则陷进地板）
- [ ] 面数（> 10 万面必须先重拓扑）
- [ ] 几何是否破洞（球会不会从洞里漏过去）
- [ ] 部件有没有焊死成一团
- [ ] Collider 生成后球能否正常挡住
- [ ] 材质在 URP 下是否正常（用 Unity Bridge 可自动配）

★ **不要跳过尺度检查** —— 这是最常见也最容易翻车的坑。

### 阶段 1：批量导入（仅在阶段 0 通过后做）

写编辑器脚本，不要手工拖：
- 清单文件（物体名 + prompt + 位置 + 旋转 + 缩放）
- 调 API 生成 → 下载 GLB → 放 `Assets/Silk/Props/`
- 记录到日志便于复现
- ⚠️ **API key 不能进客户端代码**（官方明确警告），只放本地安全存储

### 阶段 2：与白盒共存

`HouseBlockout` 结构不动，新增 `PropPlacer`：
- 在房间指定锚点位置放 AI 生成的杂物
- ★ **必须挂标记组件**（新建 `PropMarker` 或复用 `HouseMarker`），
  否则 `HouseBlockout.Clear()` 会误删

### 阶段 3：性能

- 背景道具 Smart Mesh 重拓扑到 **< 5000 面**
- `_LOD0/_LOD1` 命名（FBX 同名会变 LOD Group）
- 不要同时用「Generate mesh LODs」和 LOD Group（Unity 官方不建议）
- ★ **注意内墙±50 的网格上限**（100³），
  塞几百个高面数道具会拖垮编辑器

## 九、待验证的问题（不能靠资料回答，必须实测）

1. **中式家具还原度** —— ★ 最大不确定性，无任何评测数据
2. **重拓扑后 UV 是否还正确** —— 重拓扑改 UV，贴图可能撕裂
3. **输出尺寸的基准** —— 文档未说明是真实物理尺寸还是任意单位
4. **默认面数** —— 宣传最高 200 万面，但默认值给多少未知
5. **孔洞率** —— SimInsights 明确提到 Tripo「容易有破洞」，
   而我们刚修好墙体碰撞，孔洞意味着球会漏过去
6. **部件能否分离** —— 视频演示可以（生菜/面包分开），
   但实测报告说「常常焊死」，需确认
