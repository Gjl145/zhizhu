### ★ 两个待查问题（我**没有证据**，不猜）

**问题 1：蓝球为什么还在？**
- 调用链：`SilkSpiderBody.Start` → `BuildAnatomy()` → `HideBallVisuals()`
- `HideRenderersUnder(transform, "Body")` 用 `FindDeepChild` 递归找

- 可能：① 名字被改过 ② 时序（`SilkBuilder` 的 `Start` 晚于 `SilkSpiderBody`，
  球在 `HideBallVisuals` 之后才建）③ 那不是 `Body` 是别的球
- **★ 时序这条最可能**：`SilkBuilder` 是另一个 MonoBehaviour，
  Unity 的 `Start` 执行顺序**不保证**，球可能在蜘蛛建完之后才被创建。

**问题 2：为什么 94 个渲染器 invisible？**
候选原因（**全部未验证**）：
- FBX 的骨骼被 `AdoptExternalChain` + FABRIK 移到错误位置（尺度不对）
- `orientationFixDeg = 90` 是**推导值，从未实测**

### ★ 为什么必须用一键脚本而不是手动逐个跑

2026-10-10 那轮就是因为只跑了「自检 + 回归」就提交，漏掉 3 个真实编译错误。
**根因不是「没检查」，是检查顺序没固定、靠人每次记得跑 → 必然会漏。**

### ★★ `real_compile.py` 的原理（沙盒内可跑真编译）

Unity 自己编译时的**完整参数**被 Bee 缓存了：
```
Library/Bee/artifacts/<hash>.dag/Assembly-CSharp.rsp
```
里面有全部源文件、引用 DLL、define、langversion。
→ **把这份 rsp 喂给 Roslyn，得到的就是 Unity 会得到的错误。**

**前提**：`Assembly-CSharp.rsp` 必须存在 → Unity 至少成功编译过一次。
若 `Library` 被清过，先用 Unity 打开一次项目。

已删除的方案：`Unity.exe -batchmode`（被项目锁阻止，且**退出码仍为 0 → 假通过**）。
读 `Editor.log` 也不可行（只在 Unity 运行时更新，Unity 一关就停更，且默认是上次的编译结果）。

### ★★ 新建 `.cs` 文件后如果报 CS0246

`Assembly-CSharp.rsp` 是**上一次编译时缓存的源文件清单**。
新建文件在 Unity 生成 `.meta` 之前不在清单里 → 假报错。
`real_compile.py` 已自动从磁盘扫 `Assets/**/*.cs` 补进 rsp。

**不要改任何代码，先拿到证据。**

   **解决：`HideBallVisuals` 改成每帧或在 `LateUpdate` 检查**

★ **验证方法**：在 `HideBallVisuals` 里打印找到的物体名，或者

## 七、给下一个接手的几条忠告

### ★ 1. 一定要在 Unity 里跑过才算做了

「真编译 0 错误 + 9 项检查全过」**不代表画面是对的**。
2026-10-11 全绿的检查项下，画面是个蓝球。

★ 判据必须是：**截图** / **渲染器 isVisible 计数** / **包围盒尺寸**。
**数 Transform、数数组长度，等于没验收。**

### ★ 2. 不要在没验证 backup 之前删 fallback

删程序化建模是有道理的（用户判定它不能看），
但**应该先在 Unity 里确认 FBX 真的能接管、能显示，再删**。
我跳过了这一步，直接把用户的球留在了画面上。

### ★ 3. 设计「让用户手动接线」之前，先验证能接

`SilkSpiderAnatomy` 是运行时 `AddComponent` 的 → 编辑器里没有 Inspector → 手动拖拽**做不到**。
**任何要求用户改 Inspector 的方案，都必须先确认那个组件在编辑器里存在。**

### ★ 4. 猜的成本远高于查

我连着三次靠猜，三次都错。每次猜错 = 用户再跑一次 + 再描述一次现象。
**先把证据打出来，再动手。**

### ★ 5. 检查项本身也要验证

`check_leg_count.py` 新增第 ⑥ 项后，我注入 bug 做反向测试，**脚本报「通过」**——
正则的转义层数写错了。

★ **判据要靠反向测试验证**：「注入一个 bug → 检查项必须报错」才算合格。
（记忆里已有「判据过窄会误报」，这次的镜像是「判据写错会漏报」。）

### ★ 6. 检查范围要包含全部相关文件

`check_leg_count.py` 最初只扫 3 个文件，**把测试关卡漏在外面**，
于是 HUD 里「步足 8 条」一直没人发现。

★ **新增文件必须同步加进检查范围。**
