# 今天怎么试：贴面移动操作说明

> 2026-10-09 · 三个新文件，主文件 `SilkBuilder.cs` **一行未改**

---

## 一、Unity 里怎么操作（中文 / English 双语）

### 步骤 1 · 让 Unity 重新编译

**资源（Assets）→ 刷新（Refresh）**
或直接切回 Unity 窗口，它会自动编译。

★ 如果控制台（Console）有红字，把鼠标停在上面，
用「窗口（Window）→ Silk 编译检查 (Compile Check)」，
它会把错误写进 `Library/silk_compile_result.txt`，我来读。

---

### 步骤 2 · 找到玩家物体

新组件会自动挂到**跑酷球（Parkour player）** 上，
不用你手动添加。

它叫 **SilkSpiderSurfaceMove**（蜘蛛贴面移动）。

**★ 关键：它默认不接管输入**，所以原来的跑酷手感完全没变。
这是故意的——贴面是**新路线**，要独立验证，不能一上来就替换掉调好的手感。

---

### 步骤 3 · 三个开关（都在 SilkSpiderSurfaceMove 上）

在丝��检查器（Inspector）里找到 **SilkSpiderSurfaceMove** 组件：

| 字段 | 中文含义 | 建议 |
|---|---|---|
| `Enable Input` | 启用输入 | ★ **勾上** |
| `Build On Start` | 启动时建测试场 | 见步骤 4 |
| `Show Debug` | 显示调试线 | ★ **建议勾上**（能看到两条射线） |

---

### 步骤 4 · 建测试场（可选但强烈建议）

测试场组件叫 **SilkSpiderTestStage**（贴面测试场）。

它**不会自动建**，需要你在**场景里**随便找一个空的物体（GameObject），
挂上这个组件，然后勾 `Build On Start`（启动时构建）。

它会生成这些东西：

```
        ┌──────────────┐
        │              │  ← CeilingBeam 横梁 z=9（验证倒挂）
        │    主墙      │     10 宽 × 14 高
        │    z=14      │  ← MainWall
        │              │
   ┌────┤              │
   │台  │              │  ← CornerWall 90° 内角（验证转角）
   │阶  └──────────────┘
   └────┘
═════════════════════════  ← Floor 地面
```

★ 三组几何分别对应三个验证目标：

| 几何 | 验证什么 | 为什么重要 |
|---|---|---|
| 14 格高主墙 | **爬墙** | 你的核心疑问 |
| 3 级台阶（每级 3 格） | 上台阶不卡 | 单级 3 格 < 跳跃 apex 5.2 格，应该能上 |
| 90° 内角 | 转角不抽搐 | ★ 开源项目承认这里最难 |
| 9 格高横梁 | 天花板倒挂 | 证明「没有上下之分」 |

## 二、按键（★ 零新增按键，沿用你定的 8 键）

| 键 | 作用 |
|---|---|
| `W` `S` | 沿表面前进 / 后退 |
| `A` `D` | 沿表面左移 / 右移 |
| `Q` `E` | **沿表面法线方向下压 / 上爬** |
| `左 Shift` | 冲刺 |
| `鼠标移动` | 转视角 |

### ★★ 为什么按 E 就是「爬墙」——这是整个方案最关键的一点

听起来很反直觉，但原理是：

> **球贴到墙上之后，它自己的「上」已经不是世界的上了，而是「垂直于墙」的方向。**
>
> 所以按 E（沿法线方向）= 沿墙面往上爬。
>
> **同一套代码，地面和墙面的操作完全一样，没有任何爬墙的特判。**

这就是为什么我们**不需要**攀爬状态机——
不需要 Idle / ClimbUp / Shimmy / Mantle / Corner / SwitchSide 六个状态。

## 三、怎么判断「成了」

### 成功的样子

1. 球贴到墙前 → **自动对齐到墙面**（转 90°，「头」朝墙）
2. 按 `W` → 球**贴着墙往上走**
3. 走到墙顶 → 法线从「朝前」变回「朝上」→ **自动站到墙顶**，不用翻越动作
4. 走到内角 → 球**平顺地转 90°**继续走，不抽搐、不卡
5. 走到横梁下 → 球**头朝下挂在天花板上**走

### 失败的样子（告诉我现象，我定位根因）

| 现象 | 大概率原因 |
|---|---|
| 球在原地抖 | 射线打到了自己 → 排除自身失效 |
| 球穿墙 | `gravityMultiplier` 太小，压不住 |
| 贴墙后卡住不动 | 同上，或速度被闸门限死 |
| 转角处抽搐 | 法线插值太快 → 调 `groundNormalAdjustSpeed` |
| 球永远站不平| 表面法线判定阈值（0.7）不对 |

## 四、参数怎么调（先只调这三个）

| 参数 | 默认 | 什么情况下改 |
|---|---|---|
| `Gravity Multiplier` | 60 | 球贴不住 / 会被按进地里 |
| `Walk Speed` | 12 | 爬墙太慢或太快 |
| `Ground Normal Adjust Speed` | 4 | 落地太飘或转角太生硬 |

★ **不要一次调多个**。改一个 → 测 → 报现象 → 再改下一个。

## 六、下一个决策点：蜘蛛骨骼从哪来

这是**当前的卡点**，我需要你定。

我们做的是「程序化 IK 爬墙」，
**必须有腿的骨骼才能让腿贴住表面**。

| 方案 | 说明 | 代价 |
|---|---|---|
| **A · 买商店版** | Procedural Spider，约 $19.5~，自带模型 + 骨架 + 贴图 + 全部代码 | 花钱，但今天就能接入 |
| **B · 先不买，用代码搭假骨骼** | 用 8 条胶囊当腿，运行时算好落点摆上去。**能看到腿在动，但不是真 IK** | 零成本，1~2 小时 |
| **C · 自己建模** | Blender 做一只能跑的蜘蛛 | 耗时 |

★ 我的建议是 **B 先验证**——
因为你现在最需要知道的不是「腿好不好看」，
而是「贴面手感对不对」。
手感不对的话，腿做得再漂亮也没用。

| 资料 | 结论 |

| Unity 商店 `FS Rope Swinging System` | ★ **不是蜘蛛侠**，是《神秘海域》风格绳索摆荡。攀爬在另一个独立资产里（$40，依赖人形骨骼 + 烘焙 climb point） |
| B站「unity 制作蜘蛛侠游戏案例」 | 90 秒无解说。第 70 秒角色**整个贴在墙上横向移动**，印证了你的猜测。价值 B 档 |
| ★★ **开源 `Unity-Procedural-IK-Wall-Walking-Spider`** | ★ **今天最有价值的产出**。3233 行 MIT 开源源码，已克隆到 `Docs/参考代码/spider_ik/`。本文的方案全部来自它 |

### ★ 为什么「可读的源码」比「可看的视频」值钱

那三个视频加起来我一个字的技术参数都没拿到
（一个 90 秒无解说、一个是 UE5 而非 Unity、一个根本不是蜘蛛侠），
而开源仓库里我直接读到了：
双向球形射线、假重力公式、CCD 迭代顺序、迈步判据（IK 解不动了就想迈步）、
交替四足步态。**这才是能直接照抄的东西。**

★ 教训：找资料时**先问「有没有能逐行读的代码」**，再去找视频。
否则会在低价值视频上耗掉一整个下午。
