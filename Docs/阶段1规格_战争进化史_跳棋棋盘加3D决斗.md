## 一、项目一句话

**《战争进化史》**：2D 跳棋式棋盘上的自动战斗游戏，
玩家用钱购买士兵或升级科技；
当单位**跳到对方脸上**时，从 2D 自动战斗切换成 **3D 实时决斗**。
整体呈现**从史前到未来**的战争形态演化。

## 四、已确定的规则

### 4.1 战场形态（★ 见第五节 R-A，这是唯一的待拍板项）

需求方在原话 3 里提出这个问题，但**尚未回答**。
我给出两个方案的完整规格，需求方选定后即可开工。

---

#### 方案 A：跳棋式格点战场（★ 我倾向这个，但需需求方确认）

**核心定义**

| 项 | 规则 |
|---|---|
| 战场 | 横向长方形格点阵（建议 12 列 × 8 行） |
| 坐标 | `(col, row)` 整数对 |
| 占位 | 一格可容纳**多个**单位（这是关键，见下） |
| 移动 | 沿格线移动，一次一格；方向待定（见 R-B） |
| 跳吃 | 跨越对方单位，落到**对方所在的格**（原话 R4） |
| 战斗触发 | 两个单位进入同一格 → 触发 3D 决斗（阶段 1 暂用简化结算） |
| 攻击范围 | 按格数计算（近战 1 格、远程 2~3 格，具体待定） |
| 视觉 | 格线画得很淡或不画；仅在选中/可跳吃时高亮 |
| 单位位置 | 格内允许 ±0.3 格的随机偏移，避免「棋子在格点上」的僵硬感 |

**为什么格点但允许多单位同格**

跳棋严格「一格一兵」会导致：
- 无法形成密集阵型（米拉奇战记的军团感来自密度）
- 棋盘会非常稀疏

允许同格多单位后：
- 格子的作用变成**占位参考系 + 跳吃落点 + 攻击范围**，而不是「一格一人」
- 阵型密度可以做出来
- 跳吃依然有唯一落点

---

#### 方案 B：米拉奇战记式连续战场

**核心定义**

| 项 | 规则 |
|---|---|
| 战场 | 连续平面（横向，宽度远大于高度） |
| 坐标 | 浮点 `(x, y)` |
| 占位 | 无占位限制，单位可任意重叠（靠「挤」表现） |
| 移动 | 连续空间避让（转向 + 避障） |
| 跳吃 | ★ **无法定义** —— 没有离散格点就没有唯一落点 |
| 战斗触发 | 接触即开打（距离阈值） |
| 攻击范围 | 距离（米/单位），不按格 |

**致命冲突**：原话 R4「跳到对面脸上触发决斗」在连续空间里没有对应实现。
→ 若选此方案，跳吃与 3D 决斗必须**重新设计触发方式**（例如：单位相撞即触发）。

### 4.2 战斗结算方式

**【待拍板 R-C】** 但我的建议是**实时 tick**：

| 方案 | 说明 | 评价 |
|---|---|---|
| **实时 tick（建议）** | 单位在格子上逐帧行动，实时结算伤害 | 能复用骑砍的「前摇/僵直/反应时间」；跳吃触发决斗时衔接自然 |
| 瞬时结算 | 一回合直接算伤害数字 | 实现简单，但和 3D 决斗的衔接突兀 |

**理由**：骑砍战团的战斗核心是**单兵 AI 的时序**（前摇、僵直、反应时间、格挡、挡反）。
只有实时推进，这些才有意义。

### 4.3 骑砍三层 AI 的阶段 1 实现

**【调研】** 骑砍《战团》/《霸主》的战斗 AI 是三层架构（官方开发日志原文）：

| 层 | 职责（官方原文） |
|---|---|
| 战术 AI | 「负责为全军制定作战计划」 |
| 编队 AI | 「决定各编队如何更好地执行作战计划，同时对应急事件按一定优先级做出正确反应」 |
| 单兵 AI | 「控制战场上每个独立单位的行动，如攻击和格挡」 |

**单兵 AI 的关键机制（官方原文）**：
- 单兵 AI 有**战斗等级 1~40**，等级影响反应时间与动作速度
- 进攻时要考虑对方的**格挡方向**
- 要考虑**动作僵直时间、动作前摇时间、对手装备、战场局势**
- 会「**挡反**」：敌方进攻 → 先防御 → 挡对方向 → 抓住破绽反击
- 冲锋指令下会更侵略性，但**不是一味疯狂进攻**，会耐心寻找破绽、预判对手招数

**阶段 1 的三层映射**

| 骑砍层 | 跳棋棋盘上的对应 | 阶段 1 难度 |
|---|---|---|
| 战术 AI | 「往敌方基地推进」+ 优先打克制自己的兵 | ★ 低（先做简化版） |
| 编队 AI | 在格子上分配站位（盾在前、弓在后） | ★ 中 |
| 单兵 AI | 索敌、攻击时机、前摇/僵直、格挡、挡反 | ★★★ 高（骑砍的核心） |

★ **单兵 AI 是「骑砍战团引擎复刻」的主体，也是最有价值的部分。**
建议阶段 1 先把前摇/僵直/反应时间/挡反做出来。

## 六、调研资料：参考作品的具体机制

### 6.1 《Warfare Evolution 1 & 2》（用户截图的游戏）

**【调研】** 战争进化史 2 的信息：

- 类型：策略塔防，**横版卷轴**战场（★ 用户要改成跳棋式，不要横版）
- 核心循环：「守基地、攒钱、出兵、升级时代」
- 左右各一座主基地，血条归零即输
- 左下兵营持续产出士兵；右下可造箭塔/炮台
- **击杀敌人获得金币**，金币用于造兵、升级兵种、购买防御位
- **经验攒够 → 进化到下一个时代**，兵种/建筑/特效全换新
- 共 **7 个时代**：原始部落 → 石器 → 铁器 → 蒸汽 → 未来科技
- 兵种克制：**步兵克远程、重甲克步兵、反装甲克重甲**
- 每兵种可升级攻击/血量/特殊技能（弓手升穿透、坦克升护盾）
- 大招：陨石、冰霜、电磁脉冲，攒能量释放
- AI 会**跟着玩家的兵种调整阵容**，不无脑硬冲
- 兵种库庞大，形成**多层循环克制**关系网

**★ 1 代 vs 2 代的区别（用户截图是 1&2）**：
- 1 代：单位攻击方式都是 **1v1，谁死了下一个继续顶上**；击杀获得**经验**，经验用来进化
- 2 代：兵种分**支援型 / 步兵型 / 反装甲型 / 装甲型** 四系，支援型站在队友后面输出
- 2 代：**每个时代开始有兵种需要额外花钱解锁**才能出兵

### 6.2 《米拉奇战记》（Miragine War）

**【调研】** 用户原话 3 提到的对照作品：

- 类型：像素画风**实时自动对战策略**（PC 原作移植）
- 「**超大的横向战场地图**支持**上百个单位**同时交锋，形成极具冲击力的军团对冲场面」
- 战斗前选择兵种、消耗金币**自动派遣部队**；倒计时结束自动出击
- **全自动**：兵种生成、移动、攻击全程自动
- 兵种克制：**轻甲克重甲、重甲克轻甲、轻重均衡互制**
- **金币随时间自然回复**（★ 与《Warfare Evolution》不同）
- 战斗中可**动态调整后续兵种的建造优先级**
- 不同地图有**桥梁、隘口**等特殊地形，影响移动与交战
- 兵种划分轻甲/重甲两类护甲，**攻击伤害随护甲类型变化**
- 观感：「**百人大战的围棋场面**呈现视觉冲击力十足」
- 支持 2v2、赛季排位、战斗回放复盘

★ 注意最后一条：它的观感已经是「围棋盘」感 —— 格子是隐式的。
这支持「用大格子做跳棋战场，同时保留军团对冲观感」这个折中方案。

### 6.3 骑砍《战团》/《霸主》

**【调研】** 需求方点名要复刻的对象。

**战场规模**（战团 rgl_config.txt 的 `battle_size`）：
- 默认上限 **150 人**
- 改成 `6.0000` → 300 人
- 社区做到 500 / 750 / 1000 / 2000 人（靠 mod）
- 公式：`战场人数 = fBattleSize × (iBattleSizeMax − iBattleSizeMin) + iBattleSizeMin`
- 性能提示：「**游戏中每个单位均为独立的计算单位**，战场人数越多对 CPU 造成的负担就越大」
- Bannerlord 原版上限 1000（mod 可到 2000）

**三层 AI**：见 4.3。

**阵型**（F3 Formations）：盾墙（shields）、楔形/矛形（skein/wedge）、散兵（loose）
- 盾墙适合重甲近战，弓兵在后方排成一线
- 楔形适合近战骑兵，散兵适合骑射手和散兵
- AI 倾向：兵力悬殊 → 无脑冲；势均力敌 → 部署防守阵型

**编队指令**（F1~F7）：移动 / 跟随玩家 / 冲锋 / 前进几步 / 后退几步 / 停止 / 撤退
**F6 = 把所有单位交给 AI**

| 坐标系 | 俯视 2D，**Y 向上**，棋盘在 XZ 平面 | ⚠️ zhizhu 是 Z-up，**新工程建议 Y-up**，别混 |
| 工程位置 | **建议新建独立工程** | 见 R-F |

### 7.2 架构分层（★ 关键：让 2D 层与未来的 3D 层共用数据）

```
┌─────────────────────────────────────────┐
│  数据层  UnitStats / WeaponStats / Era   │  ← 2D 和 3D 都读这一份
├─────────────────────────────────────────┤
│  棋盘层  BoardState / MoveRules / Path   │  位置、占位、跳吃、寻路
├─────────────────────────────────────────┤
│  战斗层  CombatTick / SingleAgentAI      │  实时 tick、单兵 AI
├─────────────────────────────────────────┤
│  经济层  Gold / Shop / TechTree          │  杀敌得钱、买兵、升科技
├─────────────────────────────────────────┤
│  表现层  ColorBlockView / HUD            │  阶段 1 全是色块
└─────────────────────────────────────────┘
                    │
                    ▼
        [未来] 3D 决斗层：读同一份 UnitStats
```

★ **为什么强调这个**：原话 R7 说「3D 的战斗抄袭骑砍」「先把骑砍战团的引擎复刻出来」。
3D 决斗和 2D 自动战斗**必须用同一套数值**，否则玩家会发现「3D 里我打赢了，2D 里却被数值打死」。
→ **伤害公式、属性、克制关系只能有一处实现。**

### 7.4 几个必须注意的实现坑

1. **寻路要绕开占用的格**
   格子被单位占据 → 不可通行。跳吃是**绕过**占用格的特殊移动，不是普通路径的一部分。
   → 路径搜索与跳吃判定要分开写。

2. **同格多单位的处理**
   一格多单位时，「这一格算被占吗」？
   → 建议：**同格可共存，但不同阵营不能同格**（同格即触发决斗）。
   同阵营同格 → 允许，用于密集阵型。

3. **攻击范围与格子绑定**
   射程用「格数」而不是「世界距离」，否则大格子/小格子会不一致。

4. **实时 tick 的确定性**
   如果以后要回放（米拉奇战记有回放功能）或联机，需要固定 tick 顺序。
   → 建议：所有单位按**固定顺序**更新（不要遍历 Dictionary 的随机序）。

5. **不要用 NavMesh**
   格子战场用 NavMesh 是浪费。直接 A* on grid，格子占用表本身就是障碍信息。
