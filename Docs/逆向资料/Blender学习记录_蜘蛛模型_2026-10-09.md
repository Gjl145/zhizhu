## 二、资料与落地点

### 1. Julien Deville — Blender 蜘蛛/昆虫完整流程（Udemy，8h）

**学到**：完整工作流顺序是 参考图对齐 → 头胸 → 螯肢 → 第一条腿 → **复制适配其他腿** → 腹柄/触肢/眼 → Crease+Subdivision → UV → 绑定 → Unity 导出。

**落地点**：
- 最重要的一条：**腿只精做一条，其余靠复制适配**。我们脚本本来就是程序化生成，等价于「一条腿参数化 + 8 次实例化」，方向对。
- 参考图对齐这一步我们**没有做**。脚本靠公式定形状，缺了「用真实照片校比例」这一环。
  → 这也是本轮 `腿展/体长`、`膝拱高/腿长`、`腿长/腿根半径` 三个判据的由来：**用解剖比例替代参考图**。

### 2. Australian Museum — What is a spider（解剖权威）

**学到**（逐条落代码）：
- 头胸部 + 腹部由**细腹柄**连接 → 我们已有 Pedicel
- 头胸部 6 对附肢：螯肢 1 对 + 触肢 1 对 + 步足 4 对 → **触肢之前完全缺失**，本轮补上
- 步足 **7 节**：基节·转节·股节·膝节·胫节·后跗节·跗节
  → 5 节是 Unity 侧硬契约（`legSegments.Length != 5` 就回退默认），**没改节数**，
    改用**长度比例 + 半径 profile** 还原形态：胫节最长、膝节最短最细。
- 步足末端 2~3 爪，爪下有**毛簇**（适于光滑面爬行）→ 低模不做，但记着
- 腹部末端 3 对**纺器** → 本轮补上
- 背甲正中 **fovea** 凹陷（胸肌内骨骼附着点）→ 本轮补上
- 步足展开跨度 ≈ 体长 **2.0~2.5 倍** → 腿长判据

### 3. Spider Walker（Blender 插件，GitHub 开源）

**核心机制**：按 Center Bone 速度预测落脚点，脚偏离超阈值才迈步；腿列表顺序 = 迈步顺序。

**★ 查证了我们 Unity 侧有没有踩坑**（这是我最关心的，因为该插件明确警告）：
> 「腿控制骨不能是 Center Bone 的后代，否则同一份位移会被叠加两次，出现抖动、漂移」

**结论：Unity 侧没踩这个坑。** `SilkSpiderLimb.Solve()` 每帧用 FABRIK 解**世界坐标**，
再反算 `node.localPosition = invParentRot * (pts[i] - parentWorldPos)`。
腿根挂在身体下没问题，因为位置是每帧从世界坐标覆盖的，不存在位移累加。

**可借鉴**（Unity 侧尚未实现，列为待办）：
- `Prediction Distance`：按身体速度把落点**向前预测**，避免快跑时腿拖在身后
  → 我们现在有 `predictVel`，方向一致，量级待调
- `Min/Max Step Time`：限制单步最短/最长时长，防止短距离动作瞬间跳变
  → **我们没有**，可能是「移动两步就重来」的另一个成因
- `Speed Step Scale`：步幅触发距离随速度变化

### 4. Blender Artists — 蜘蛛 IK 讨论

**学到**：IK 约束作用于骨的**尾部**，所以控制骨需要一小段自由延伸段；
骨骼朝向不一致（roll 乱）会导致 Unity 里骨骼轴向错误、IK 失效。

**落地点**：导出参数保持 `primary_bone_axis='Y'` / `secondary_bone_axis='X'`。
**待办**：导出前统一 recalculate roll（资料建议 `Recalculate Roll → Global +X`）。

### 5. Blender → Unity FBX 导出（多份资料交叉确认）

**学到**：
- `Apply Scalings` 必须选 **FBX Units Scale**，否则 Unity 里缩放差 100 倍
- Forward `-Z` / Up `Y`；Unity 侧勾 `Bake Axis Conversion`
- `Add Leaf Bones` 关闭 → 我们已做
- 每个顶点最多 **4 个骨骼影响**（Unity 默认）
  → **我们目前是「最近骨骼 100% 权重」，每点只有 1 个影响，天然合规**，
    但也意味着关节处不会有平滑过渡。FBX 接入 Unity 后可能需要改成双骨权重。

### 6. Blender 4.1+ 平滑着色变更（官方 release notes）

**学到**：`Auto Smooth` 复选框已移除，替代是 `Shade Smooth by Angle`
（Python: `bpy.ops.object.shade_auto_smooth(angle=...)`）。

**落地点**：尚未用上。当前脚本报 `Material.use_nodes` 弃用警告（Blender 6.0 将移除），
但不影响运行。

## 三、本轮踩到的坑（都是自己写的检查器/脚本出错）

### 坑 1：判据的基准跟着被调的参数一起动
`足端间距 > 0.6 × 腿长` 这个阈值是在腿长 3.6r 时校准的。
**腿一加长到 6.4r，倍数阈值就自动变严 → 必然失败。**
也就是说：只要把腿改成真实比例，这个判据就一定拦下来。

判据在惩罚正确方向。→ 改成以**体长**为基准。

**教训**：别让判据的隐含基准跟着你正在调的参数一起动。

### 坑 2：扫描脚本的分母漏乘 BALL_RADIUS
`sweep_yaw.py` 把「6.4（r 的倍数）」直接当绝对长度用，
所有比值虚高 25%：脚本报 0.685、主脚本报 0.55，同一个绝对间距 4.386。
照着扫描结果改模型，会改错。

### 坑 3：文本替换静默失效（同一个错犯了两次）
- `sweep_yaw.py`：`code.replace('LEG_YAW_DEG = [-96.0, ...]')` —— 我后来改了 yaw 值，
  替换目标不存在 → 没报错，实际跑的一直是文件里的 yaw，
  却打印着参数值。**差点据此改错模型**。
- `render_spider_preview.py`：`code.replace('\nmain()\n')` —— 源码格式一变就失效。

**教训**：改用什么加载/替换方式，先问「怎么确认它真的生效了」。
现在 sweep 里加了 `if "[-%.4f, -%.4f," % (outer, inner) not in code: sys.exit(9)`。

### 坑 4：检查器写死预期值
`check_spider_model.py` 写死 `EXPECT_MESH=78 / MAX_TRIS=3000 / MIN_SEP_RATIO=0.6`，
我补了部件后它连报三条失败。

**这比误报更危险**：写死的检查器会**逼人把模型改回去**，
或者更糟 —— 让人为了让它过而去放宽检查。

→ 改为从 `make_spider.py` 解析阈值（单一事实来源），解析失败直接报错，不给默认值兜底。

### 坑 5：判据只防方向错误，不防幅度不足
`check_standing` 原本只判「膝 > 腿根」「膝→足端下降够大」，
膝高 0.88（比例 0.11）也照样通过 —— 但渲染出来腿是**水平尖刺**，完全不像蜘蛛。

**所有数值检查全过，只有看图才发现。** → 补「膝拱高/腿长 ≥ 0.18」「腿长/腿根半径 ≤ 35」。

### 坑 6：判据只检查了部分自由度
实测发现：跨侧最小间距**对 inner yaw 完全不敏感**（26/30/34/38/42 五档结果一模一样），
因为瓶颈永远是镜像的 `leg_L_4 ↔ leg_R_1`，只由 outer 决定。

→ inner 原本是一个**根本没被任何判据覆盖**的参数，可以随便乱填。
→ 补「同侧最小间距」判据。
