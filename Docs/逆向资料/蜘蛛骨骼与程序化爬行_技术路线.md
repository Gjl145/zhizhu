# 蜘蛛骨骼与程序化爬行 —— 技术路线定稿

> 2026-10-09 · 来源：3 份外部资料 + 1 份可读源码
> ★ **本文推翻了「照人形攀爬状态机做」的路线。**
> 用户原话：「蜘蛛的攀爬是不是不需要这么多的东西，好像可以直接去抓住墙面攀爬」
> → 实测：**不只是不需要，是根本不该有状态机。**

## 一、★★★ 路线变更：假重力贴面取代攀爬状态机

### 原计划（今天作废）

照Advanced Traversal System v1.12 做人形攀爬状态机：

| 状态 | 我们的实现 |
|---|---|
| Grab / Idle / ClimbUp / ClimbDown | 球贴墙上下 |
| Shimmy | 沿边横移 |
| Mantle | 翻上平台 |
| Corner / SwitchSide / Reach | 复杂，砍掉 |

**为什么作废 —— 三个致命问题：**

1. **球没有边缘可抓**。攀爬状态机的核心是「找到一条能挂住的边沿」，
   而蜘蛛在**整面墙**上都能走，根本不需要找边。
2. **球没有手**。Braced / Freehang 两套动画分支全部失去意义 ——
   分支的意义是表现「脚蹬墙」vs「只有手挂着」，球两者都不是。
3. **状态机 bug 会连锁**。7 个状态 × 转移条件 × 空间检查，
   任何一处判错就连锁卡死。这是本项目已经栽过 8 次的坑（CS0103 同类）。

### 现在的做法：两个球形射线 + 假重力

开源项目 `Unity-Procedural-IK-Wall-Walking-Spider`（PhilS94）的核心只有三步：

| 步骤 | 代码 | 作用 |
|---|---|---|
| 1. 向下打**球形射线** | `Physics.SphereCast(pos, r, -up, ...)` | 找到「脚下的面」 |
| 2. 向前打**球形射线** | `Physics.SphereCast(pos, r, forward, ...)` | 找到「前方的面」 |
| 3. 朝法线插值旋转 + 假重力 | `Quaternion.Slerp(...)` / `AddForce(-normal * g)` | 把蜘蛛压在该面上 |

**为什么这就够了 —— 关键洞察：**

> **只要把 `transform.up` 对齐到命中面的法线，「垂直」方向就被重新定义了。**
> 地面、墙面、天花板、90° 转角，全部变成同一个坐标系下的「地板」。

→ **同一套代码，零特判。** 走到哪都是地板，所以不需要攀爬状态。

★ 这与本项目MEMORY 第十节记的 GDC 2019「放弃垂直天空蛛丝」是同一个思路：
**不要为特殊情况写分支，要让坐标系吸收特殊情况。**

## 三、五个可直接照抄的核心机制

### 1. 假重力（`Spider.cs` FixedUpdate）

```csharp
// ★ 用 groundNormal，不是插值后的法线 —— 注释里作者自己强调过
rb.AddForce(-grdInfo.groundNormal * gravityMultiplier * 0.0981f * getScale());
```

**不用 Unity 的物理重力**，沿命中面法线自己施力。
→ 所以球能站在天花板上，物理引擎完全不需要知道这件事。

### 2. 法线插值（不是瞬间对齐）

```csharp
Vector3 slerpNormal = Vector3.Slerp(transform.up, grdInfo.groundNormal,
                                      0.02f * normalAdjustSpeed);
```

★ 关键：**Slerp 而不是直接赋值**。瞬间对齐会在转角处抖动。
而且地面的调整速度比墙面**慢**（`groundNormalAdjustSpeed` vs
`forwardNormalAdjustSpeed`）—— 落地要稳，撞墙要跟手。

### 3. CCD 反向运动学（`IKSolver.cs`）

```csharp
int k = mod((i - 1), joints.Length);   // 从最后一个关节开始，倒着推
for (int i = 0; i < joints.Length; i++)
{
    int k = mod((i - 1), joints.Length);
    solveJointCCD(ref joints[k], ...);
}
```

- **从末端往根部解**（CCD 的标准做法）
- `mod()` 自己实现，因为 C# 的 `%` 对负数返回负值
- 三个退出条件：错误 < 容差、单次迭代改善 < 阈值、迭代满 10 次
- 奇异点保护：`toTarget` 长度 < `singularityRadius` 时跳过该关节

### 4. 迈步条件（`IKStepper.cs`）

```csharp
minDistance = 0.2f * chainLength;   // Awake 时算一次
```

> **一条腿想迈步 = IK 已经解不动了**（末端离根部太远，超过链长 20%）。

★ 这是整套系统最优雅的地方：不需要任何「步态相位」计时器，
解算失败天然就是迈步信号。作者的注释原文：
> "A leg desires to step if the IK solver can not solve the leg sufficiently anymore."

### 5. 交替四足步态（`IKStepManager.cs`）

```csharp
public enum StepMode { AlternatingTetrapodGait, QueueWait, QueueNoWait }
```

> **Alternating Tetrapod Gait = 真实蜘蛛的步法。**
> 8 条腿分成 A / B 两组，计时器在两组间切换 ——
> 同组腿一起动，永远不会和另一组撞上。

另有两种队列模式（会互相阻塞）。**我们要第一种。**

## 四、★ 我们要用到的骨骼需求（★ 这是接入前必须确认的）

开源项目的蜘蛛模型有**每条腿 5 个关节 + 1 个末端执行器**。
作者在商店页明确写了接入自定义模型的要求：

> - 每条腿必须有**足够多的关节**（自带模型是 5 个 + 末端）
> - **第一个关节必须绕蜘蛛根骨的上轴旋转**
> - 其余关节必须能**弯曲**（例如绕局部 Z 轴）
> - 腿长 / 身体长 的比例要接近

★ **这直接决定了「骨骼从哪来」的问题。** 我们需要：

| 需求 | 说明 |
|---|---|
| 8 条腿 × 5 关节 | 40 个 Transform |
| 每关节一个 `JointHinge` | 需作者改模型则改 prefab |
| 材质与贴图 | — |
| 脚步触地| 射线打点 + CCD 自动解决，不需要 IK 目标动画 |

**我们不需要的东西**（作者自己列的限制）：

> "This asset does not include any animation clips.
> All animation is fully procedural."

→ **全部程序化，零动画片段。** 这对我们是好事 ——
不用去弄 FBX 动画序列。

## 五、三个外部资源的实际结论

### 1. B站「unity 制作蜘蛛侠游戏案例分享」（BV1fV5szDEuU，90 秒）

| 项 | 内容 |
|---|---|
| UP | 车到山前_csdn |
| 工程| `ThirdPersonProject`（Unity 6） |
| 角色 | **有骨骼的蜘蛛侠模型**（红蓝配色人形） |
| 标题字幕 | **「向量坐标吸附系统」** |
| 音频 | mean_volume −11.4 dB，但转写返回 0 段 → 按 skill 做法改抽帧 |

**抽帧看到的内容（23 帧全看过）：**

- 大量**城市街道摆荡**（丝线、屋顶、廊桥）
- ★ **第 70 秒：角色整个贴在墙面上做横向移动** ——
  和用户猜的「直接抓墙面爬」完全一致
- ★ **第 90 秒（最后一帧）：角色是「蹲姿、四肢着地」的爬行姿态**，
  身体压得很低、腿朝侧面张开 —— **不是攀爬竖墙，是在地面上爬**
- 丝线是 `LineRenderer` 画的折线，有明显的**分段弧线**（第 15 帧可见）
- 丝线落点是**吸附在几何体表面**的（第 33 帧可见丝线连到墙上一点）

★ **第 90 帧这条信息很有价值**：它说明「蜘蛛式四肢爬行」和
「人形攀爬竖墙」在这个项目里是**两个不同的能力**，
作者两者都做了。而我们的球只需要前者的视觉 —— 四肢着地。

★ **「向量坐标吸附系统」这个标题值得记住** ——
它说的就是「把角色吸附到表面法线上」，与今天的假重力方案**是同一件事**。
但他用的是人形骨骼 + IK，我们用球 + 无 IK，成本差一个量级。

★ **价值判断：B 档。** 它证明了「贴墙爬」这个交互在 Unity 里做出来是顺的，
但没有技术细节，不能照抄。

### 2. B站「虚幻引擎5 一步一步制作蜘蛛程序动画」（BV1Rw411u7Jd，58 分钟）

转写中（后台跑，约需 15-30 分钟）。
★已确认音轨 mean_volume −22.4 dB，**有声音**，是真教程。
→ 完成后补分析。

### 3. ★★ Unity 商店 `FS Rope Swinging System` —— **不是蜘蛛侠**

用户以为它是蜘蛛侠插件，**实际不是**：

| 项 | 实际内容 |
|---|---|
| 定位 | **受《神秘海域》（Uncharted）启发的绳索摆荡** |
| 作者 | Fantacode Studios |
| 版本 | 1.2.4（2025-12-09） |
| 大小 | 48.2 MB |
| 价格 | $17.48 |
| Unity | 2022.3.2f1 起，Built-in/URP/HDRP 兼容 ✓ |
| 评分 | 「not enough ratings」 |
| 评价 | 「摆荡来回时手感比较真实，但**不能在空中直接改变摆荡方向**」 |

★ **重要发现：它依赖的攀爬系统是另一个独立资产** ——
`FS Parkour And Climbing System`（$40，25.1 MB，32 个攀爬动画 + 14 个跑酷动画）。

**那个攀爬系统的技术路线：**

> "The climbing system uses a mix of **authored and procedural** animations."
> "Uses **Inverse Kinematics (IK)** to place the hands and feet dynamically while climbing."
> "Supports **Braced Hang and Free Hang** climbs."
> "**Bake climb points** on ledges with a single click."

★ 结论：**它是「预放置攀爬点 + 烘焙」路线**，需要美术在关卡里
手动/批量烘焙 climb point。而且它依赖人形骨骼（手、脚IK）。

**→ 对我们的价值：作为「别人怎么设计攀爬手感」的参考文档，不能直接用。**
它的官方文档站（fantacode.gitbook.io）有详细的参数说明，值得读。

## 六、★★ 今天要做的（骨骼优先，丝线摆荡全pass）

用户明确：「什么发射蛛丝拉，什么摆荡拉，今天都不需要去管啊，
都直接先pass掉，**先做骨骼**吧。再看看能不能接入」

### 阶段划分

| 阶段 | 内容 | 前置|
|---|---|---|
| **A** | 贴面移动本体：假重力 + 双射线 + 法线插值 | 无 —— **不需要骨骼** |
| **B** | 蜘蛛骨骼模型接入 | 需要一个 8 腿 × 5 关节的模型 |
| **C** | CCD IK 让腿贴住表面 | B |
| **D** | 交替四足步态 | C |

★ **A 阶段不需要骨骼，今天就能做完并且看到效果。**
这跟用户的既定迭代循环一致：一次一个特性，每个特性配独立测试场。

### ★★ 卡在 B 阶段的问题：**骨骼模型从哪来**

我们目前**没有任何蜘蛛模型**。三条路：

| 方案 | 说明 | 代价 |
|---|---|---|
| 1. 程序化生成骨架 | 用代码建 8 条腿的 Transform 链 + 胶囊当腿 | ★ 零成本，今天就能做，**但不是真骨骼动画**（其实是程序化摆腿） |
| 2. 买商店版 Procedural Spider | $19.5~，自带模型 + Rig + 贴图 + 全部代码 | 花钱，但**今天就能接入** |
| 3. 自己建模 / 找免费模型 | Blender 做一只能跑的蜘蛛 | 耗时（用户「骨骼这个我还没学习过」） |

★ **我的判断**：先做 A 阶段（贴面移动），
它**完全不依赖骨骼**，能立刻验证「假重力贴面」这条路走不走得通。
再决定 B 阶段的模型来源。

## 八、★★ 本次的方法论教训

### ★ 用户一句话点破了僵持的方案

我准备按ATS 做了整天的攀爬状态机（边缘检测、空间检查、
抓取点预判、7 个状态、转角、换手），用户一句
「蜘蛛的攀爬是不是不需要这么多的东西，好像可以直接去抓住墙面攀爬」
直接把方案推翻。

**教训：用户对自己领域的直觉常常比我的资料推导更准。**
我做了一整天资料检索，得到的却是「人形攀爬需要这些」——
而用户要的是「蜘蛛」，**根本不是人形**。

### ★ 搜索要找「可读的源码」，不只是「可看的视频」

今天真正的价值来自一个 3233 行的开源仓库，
而不是那三个视频（一个是 90 秒无解说、一个是 UE5 而非 Unity、
一个根本不是蜘蛛侠）。

★ **判定标准要前置**：找资料时先问「有没有能逐行读的代码」，
再去找视频。否则会在低价值视频上耗掉整个下午。
