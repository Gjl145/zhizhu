## 四、功能可行性逐项对比（已查证）

| 功能 | UE 方案 | Unity 方案 | 差异 |
|---|---|---|---|
| **八足蜘蛛程序化行走** | Locomotor（FABRIK） | ★ **Animation Rigging 包的 FABRIKConstraint（官方）** | **持平** |
| 丝线渲染 | SplineMesh + Niagara | LineRenderer / TrailRenderer | 持平 |
| **丝线物理摆荡** | Chaos + 自写约束 | 自写约束链（**我们已写 1079 行**）| **持平（已有）** |
| 碰撞 | Chaos SphereCast | Physics.SphereCast（**已实现**）| **持平（已有）** |
| 相机避障 | 自写 SphereCast | 已实现 OverlapSphere+SphereCast | **持平（已有）** |
| 次级运动 | Control Rig Physics | Animation Rigging + 自写衰减 | UE 省 3~5 天 |
| 投射物特效 | Niagara（Trails 模板现成）| VFX Graph（需手动 Previous Position）| UE 省 2~3 天 |
| 白盒 CSG | Godot 原生 CSG | **Unity 无内置 CSG**（ProBuilder 需装包）| 持平 |

### ★ 关于「八足蜘蛛」的关键查证

用户看到的是 UE 的 Locomotor 插件，但——
> **Unity 的 Animation Rigging 包有官方 `FABRIKConstraint` 组件**，
> 且社区已有成熟实现：
> - `nccvector/spider-walk-unity3d`（Unity3D 的FABRIK 蜘蛛行走）
> - `frabulous/ProjectArakne`（Unity 的程序化蜘蛛在地形上行走）

**即八足蜘蛛在 Unity 里也是成熟方案，不是「UE 独占」。**

### 净账

| 项 | 天数 |
|---|---|
| UE 独占优势（特效 + 次级运动）| **省 5~8 天** |
| 下载 UE | 耗 1~3 天 |
| 迁移重写 | **耗 10~29 天** |
| **净结果** | **亏 7~24 天** |

## 五、结论：不换

### 三条理由

**1. 视频能直接用 —— 这个前提不成立**

用户看到的是 UE 插件，但逐项查证后：**10 项功能里 8 项两引擎持平**，
且其中 3 项（摆荡物理、碰撞、相机避障）**我们已经实现了并调过手感**。
真正 UE 占优的只有 2 项，合计省 5~8 天。

**2. 迁移成本远大于收益**

实测网络 0.94 MB/s → 下载 15~39 小时；重写 4594 行 → 10~29 工作日。
**净亏 7~24 天。**

**3. ★ 项目最贵的资产是「结论」而非「代码」**

124 次提交换来的：
- 摆荡物理按 **Insomniac GDC 2019 官方公式**实现（重力 98 = 10 倍地球重力）
- 锚点评分的**直行/转向分离**（官方 P57）
- 相机穿墙的 **OverlapSphere 预处理**（Unity SphereCast 的固有陷阱）
- 9 份 GDC 官方 PDF + 实算的调参表

★ **这些结论搬到 UE 后一行代码都不用改**，
但**重新调参的过程要在 UE 里再走一遍**——这才是真正的成本。

## 六、什么情况下应该换

诚实地说，有几个条件会推翻上面的结论：

| 条件 | 是否成立 |
|---|---|
| **你已经有 UE 工程/资产，不想从零开始** | 需你确认 |
| **你确定要做八足蜘蛛，且愿意装 Animation Rigging** | Unity 同样可做 |
| **Unity 版本（2022.3）某天不再支持你需要的包** | 未发生 |
| **你打算做 VR/影视级渲染** | Unity HDRP 也可，但 UE 更强 |

★ 若第一条成立（你已有 UE 资产），结论会反转——因为迁移的最大成本
「从零搭建」已经不存在了。**这一点我无从得知，需要你确认。**

## 七、建议的下一步（不换引擎的前提下）

| 优先级 | 事项 | 工作量 |
|---|---|---|
| 1 | **门洞墙垛**（`BuildDoorways` 只有门楣，门没挖通）| 0.5 天 |
| 2 | 二层楼板洞口（楼梯上来要能出）| 0.5 天 |

★ 第 1、2 项是**内容缺失**，不是引擎能力不足——换引擎不会自动完成。
★ 第 3 项能直接验证「Unity 能不能做八足蜘蛛」，这是你最想要的功能。
建议**先做第 3 项验证**，若 FABRIKConstraint 满足需求，就彻底排除换引擎的念头。
