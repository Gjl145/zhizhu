## 一、视频 1：BV1X88c6iETw（UE5 程序化蜘蛛，TechLim Studios，约 75 分钟）

转写：`Docs/参考视频转写/BV1X88c6iETw_UE5程序化蜘蛛_转写.txt`
（转写错字很多，以下为按上下文校正后的机制还原。**这是上一任 AI 存了却从未读过的文件。**）

这是「MultiplexSpider 程序化步态」完整教程：**零关键帧、零动画剪辑**，
全部步态由蓝图程序生成。核心结构分五层：

### 1. IK Rig 层
- 全身 IK（Full Body IK）解算器，根骨设为 root。
- 8 条腿末端各建一个 **IK Goal**。
- 每条腿根挂一个**虚拟骨（virtual bone）**，IK Goal 附加到虚拟骨上
  → Goal 可以被场景组件在世界空间里随意拖动，骨骼跟着走。

### 2. 单腿循环（每条腿一个「腿管理器」组件，挂在虚拟骨下）
这是全片的核心逻辑：

```
每帧：
  vel = 角色速度
  目标球位置 = 当前位置 → VInterpTo(当前位置 + vel × 0.5)   ← 落点预测：提前半秒
  t += deltaTime                                            ← 步周期 0→1
  足端 = Lerp(本次起点, 目标球位置, t)                        ← 从旧落点走向新落点
  高度抬升 = 曲线(t) × 75                                    ← 抬脚曲线，见下
  当 t ≥ 1：
      t = 0
      若 vel > 0：replant = true → 记录新起点，继续下一步
      若 vel = 0：不 replant，足端插值回默认站姿位置
```

**抬脚曲线**：一条曲线资产，关键帧 0s=0 → 0.5s=1 → 1s=0（可调切线平滑），
值乘以 75 加在高度轴上 → 足端走出「抬起-落下」的弧线。

**起步/停步**：
- 角色蓝图检测「速度从无到有」→ 触发一次 `MoveLegs` 事件（带 0.2s 启动延迟），
  设 `startMoving = true`。只触发一次，避免每帧重复调用。
- 速度归零 → 足端插值回初始位置。
- 半空起步问题：无速度时立即把足端拉回站位（否则空中腿悬在旧落点）。

### 3. 步态序列（盒子循环）
- 8 腿分**两个对角组**：A+C+E+G 一组、B+D+F+H 一组（先动四条，再动另外四条）。
- 组间延迟 = 单步延迟 × 0.5（第一组走一半，第二组跟上）。
- **组内每条腿有本地启动延迟**（0 / 0.2s 交错）——作者明确说这是为了
  「打破机器人感」：四条腿完全同步会像机器人。

### 4. 参数化（随移速联动）
- 单步延迟随移速变：走速 120 → 延迟 1s；跑 → 0.5 / 0.75。
- 抬脚高度每腿随机 15~75 → 每条腿弧线不同，进一步去机械感。

### 5. 地形贴合
- 从预测落点向上 300 打 Line Trace，命中点即新落点（+少量偏移）。
- 腿随地形高度变化，全程无穿模、无滑动。

### 视频里的踩坑（值得记）
- **IK Rig 根键设错** → 网格整体上飞。原因：虚拟骨的父子关系挂错，
  根一分离，整个网格跟着飞。修复 = 把虚拟骨重新挂到正确父级。
- 模型导入方向与代码方向差 90°（与我们 FBX 朝向修正问题是同一类坑）。

## 二、视频 2：BV12F411P71f（Unity Animation Rigging IK 腿部动画，约 10 分钟）

转写：`Docs/参考视频转写/BV12F411P71f_UnityIK腿部动画_转写.txt`
★ 与交接文档「Unity 程序化腿部 IK」是同一条视频（已实现「腿互斥可配置」）。

### 核心思路（官方程序化动画教程改）
1. **玩家控制的是身体，不是腿**。
2. 腿的位置向下打射线 → 地面碰撞点 = 落点。
3. 身体移动时，**落点钉在原地不动**，IK 插件自动算出腿部姿势（腿被拉长）。
4. 检测「钉住的落点」与「射线检测点」的距离，超过阈值 →
   播一段插值动画把落点搬到新位置（山形函数做抬脚路径，stepHeight / stepSpeed 参数）。
5. **互斥腿**：同行/同列的脚不能同时抬起 → 把互斥的 target 脚本互相拖进 Leg1/Leg2 列表。
6. 落点偏移向量（前后/左右偏移）定义四条射线的起点，四角对称、符号取反。
7. **身体贴坡**：单独脚本射线检测脚下坡度 → rigidbody 旋转身体对齐；
   备选方案：按四条腿的高度差计算身体倾角。
8. 模型：Blender 长方体搭的简易四足，腿原点在根部，导出 FBX。
9. 坑：模型导入时旋转了 90°，**代码里的方向和模型方向不一致**，写代码要留意。

### ★ 我们项目与它的差异（重要）
- 它是 **Y-up**、腿射线沿 −Y；我们是 **Z-up**，射线沿 −Z，且用表面法线体系
  （地面/墙/天花板同一套逻辑，比视频的方案覆盖面更广）。
- 它用 Animation Rigging 的 TwoBoneIK（2 节骨骼）；我们是 5 节链 FABRIK。
  **2 节 IK 天然不会反拧，5 节 FABRIK 会** → 这就是交接文档 P3「关节限位」的根源。

## 四、与本项目映射表（学了就要用）

| 视频机制 | 本项目状态 | 差距 |
|---|---|---|
| 落点预测 vel×0.5 | ⚠️ 只有单向 footRay | 换点预测缺「多向射线+预测位移」 |
| 抬脚曲线 0→1→0 | 已有抬腿逻辑 | 曲线形式待对齐视频做法 |
| 双组对角步态 + 组内交错延迟 | 已有交替四足（dutyFactor=0.65 占空比式） | 是连续占空比，不是视频的「组序列+本地延迟」，去机械感可借鉴 |
| 抬脚高度每腿随机 | ❌ | 小改动，去机器人感收益大 |
| Line Trace 贴地形 | ✅ 已有（表面法线，比视频强） | — |
| 距离阈值换点 | ✅ 已有 | 缺残差判据 |
| 腿互斥 | ✅ 已实现（exclusiveLegsCustom） | — |
| Smart Body Position | ✅ 已实现 | — |
| 关节旋转限位 | ❌ FABRIK 无限位 → 腿会反拧 | P3，需从 FBX rest pose 反推 |
