## 零、这个视频是什么

**真教程，81 段全部有效**，6 分 10 秒讲完一个完整可跑的效果。
没有废话，是照着做就能出结果的教程。

它做的是**视觉欺骗**：平面网格在渲染时被推到球面上。
**碰撞体完全不动**—— 教程全程没碰碰撞、没碰物理。

★ 这就是它「比重力切换好做」的根因：
**重力切换要改物理，改物理就有玩家适配问题（那个UP主晕了两个小时）；
球形世界只改渲染，物理一行不动。**

## 一、教程的完整步骤（含全部参数值）

### 1. 建材质参数集合（MPC）

在内容浏览器建文件夹 `Material` → 创建**材质参数集合**，命名 `MPC_Curve`。

添加 4 个参数：

| 参数 | 类型 | 默认值 | 作用 |
|---|---|---|---|
| `Flat Distance` | 标量 | **100** | 效果完全为零的距离 |
| `Base Distance` | 标量 | **1000** | 效果完全拉满的距离 |
| `Power` | 标量 | **5** | 曲线对比度 |
| `Direction` | **向量** | R=0，**G=1，B=1** | 偏移方向 |

★ **Direction 的 G 和 B 设为 1，R 保持 0** —— 这是球形化的方向，
R=0 表示 X 轴不动，G/B 都推 → 形成向内收缩 + 向上的联合偏移。

★ **为什么用材质参数集合而不是直接改材质**：
> 「你更改参数时，它会在**所有使用处统一应用**。」
> 即：一次修改，全场生效。这就是 Memory 里那条「参数全部接线」原则的等价物。

### 2. 建材质函数（MFCurve）

节点链（按教程顺序，这是核心）：

```
WorldPosition − CameraPosition → 物体与相机的距离
  ↓ Subtract
  ↓ Collection Parameter(Flat Distance) → Divide      ← 除以 FlatDistance 归一化
  ↓ Collection Parameter(Base Distance)
  ↓ Power                                       ← 调整对比度，让效果更明显
  ↓ Collection Parameter(Power)
  ↓ Multiply
  ↓ Collection Parameter(Direction)                   ← 最后乘方向向量
```

★ 注意这个顺序的精妙之处：
**先减 Flat Distance，再除以 Base Distance** ——
所以真正的衰减区间是 `[FlatDistance, BaseDistance]`，
**这段区间内才开始弯曲**，而不是从 0 就开始。

### 3. ★ Pivot 处理（漏了这步网格会被拉歪）

这是教程里最容易漏、也最关键的一步：

1. 用建模工具建一个 Box，**长宽高的细分都设为 50**
   （★ 细分是必须的——顶点太少，弯曲后是折面不是球面）
2. 在关卡里创建它
3. 左侧向下滚动找到 `Transform` → 选 `Pivot`
4. 点 `Enable Snap` → 拖动 `Snap` → **把 Pivot 拖到左下角**
5. 点 `Accept`
6. 切回 `Select` 模式

★ **为什么要拖到左下角**：
> 「我们更改 Pivot 使其与默认地图中立方体的 Pivot 匹配」
> 然后删掉刚创建的立方体，把默认地图的 Playground 网格的静态网格换成自己建的。

→ **因为球形化的方向偏移（Direction 里有 G 和 B）是相对于 pivot 的**
。pivot 在中心 → 整块网格会平移；pivot 在左下角 → 只做预期的形变。

### 4. 接线到材质

把 `MFCurve` 加到材质上 → 连到 **`World Position Offset`**。

★ **UE5 有 `World Position Offset` 这个内置输入**，Unity 没有对应物
（Unity 必须在 vertex 里手写 `positionCS`），这是引擎差异最大的地方。

### 5. 看效果

关卡里网格会变形为球形。**播放并移动角色 → 之前不可见的网格会进入视野**
（因为球心跟着相机，曲面被"卷"起来了）。

调整 `MPC_Curve` 里的 `Power` 可以增强效果。

## 二、Unity 侧实现（视频是 UE5，项目是 Unity 2022.3）

### 2.1 ★★ 核心公式（可直接写进 ShaderLab）

```hlsl
// vert 里
float3 wp    = TransformObjectToWorld(positionOS.xyz);
float3 toCam = wp - _WorldSpaceCameraPos;
float  dist  = length(toCam);

float t = saturate((dist - _FlatDistance) / max(_BaseDistance - _FlatDistance, 1e-3));
t = pow(t, _Power);

float3 bent = wp - t * _Direction.xyz;
positionCS = TransformWorldToHClip(bent);
```

**这就是全部**。与 UE 的差异只有两点：

| | UE5 | Unity |
|---|---|---|
| 挂载点 | 材质的 `World Position Offset` 输入 | 手写 vertex，覆盖 `positionCS` |
| 相机位置 | `CameraPosition` 节点 | `_WorldSpaceCameraPos`（内置） |
| 全局参数 | MPC 材质参数集合 | `Shader.SetGlobalFloat/Vector` |

★ **Unity 里没有材质函数概念**，
所以 MPC 要用 `Shader.SetGlobalFloat("_FlatDistance", 100f)` 之类替代，
放在一个 `MonoBehaviour` 里统一驱动（对应教程的「一次修改全场生效」）。

### 2.2 ★ 已知的坑（视频没提，但一定会撞）

**坑一：视锥剔除会出错**

顶点被 shader 推走了，但 Unity 用来做视锥剔除的 AABB 是原始网格的。
→ 远处的物体会被**错误剔除**，或者近处的突然消失。

处理：
```csharp
// 三选一
renderer.bounds = 扩大的Bounds;            // 运行时手动放大
// 或
Material.enableInstancing + 手动 bounds
// 或：网格细分足够密 + 距离阈值内才启用效果
```

**坑二：法线会错**

顶点位置被改了，`normalOS` 没改 → **光照算错，物体看起来像被拉扁了**。

处理：必须**同时旋转法线**——
```hlsl
float3 bentN = normalize(mul((float3x3)bentMatrix, normalOS));
```
★ 这是球形世界最容易出「看起来很假」的地方。

**坑三：Fog / 阴影 / 反射都会错**

雾是按距离算的，顶点移了但着色器里的 distance 还是原始距离。
阴影需要自定义 ShadowCaster 同样做位移。

**坑四：低端实现（可能更适合本项目）—— 只改Y**

业界常用的简化版（Unity 侧常见于《旷野之息》《原神》《巫师3》的远景）：

```hlsl
// Δy = d² / (2R)，泰勒展开
float d = length(toCam.xz);
wp.y -= d * d * _Curvature;   // _Curvature = 1/(2R)
```

★ **参数范围（业界实际值）**：`R` 通常取 **2000~8000**。
`R = 3000` 时，1000 单位远处的下沉约 **167 单位**。

★ 只有 XZ 距离参与 → **远处不会向内收缩**，比完整球形化便宜得多，
适合「只要地平线看起来弯」的需求。

## 三、业界参数速查

| 参数 | 值 | 来源 |
|---|---|---|
| R（球半径） | 2000 ~ 8000 | Unity 社区实测 |
| R=3000 时1000 单位外的下沉 | 约 167 单位 | 同上 |
| 顶点细分（UE 教程） | Box 三轴各 **50** | 本视频 |
| 效果起始距离 | 视相机类型而定 | 本视频用 100 / 1000 |
| 完整球面公式 | `x=r·cosθ·sinφ` `y=r·sinθ·sinφ` `z=r·cosφ` | Shader Graph 实现 |

### 完整球面 vs 远景球面化

| | 完整球形化 | 远景球面化（简化） |
|---|---|---|
| 参与计算 | 全部三轴 | 只用 XZ 距离 |
| 效果 | 几何上真的包在球上 | 只是远处下沉 |
| 成本 | 高（含法线、剔除、雾） | 低 |
| 适配固定相机角度 | 否（kianbennett 明确说不适合） | 是 |
| 适用 | 星球、小行星 | 开放世界远景 |

★ 语雀那篇译文的作者明确警告：
> 「此着色器确实具有局限性：当对象的顶点经过转换时，**其渲染范围保持不变**。
> 这意味着当网格物体仍在屏幕上时，该对象可以**使相机的视锥体变成圆锥形**，
> 如果相机处于某个角度，则该对象将消失。**因此此着色器最适合具有固定摄影机角度的游戏。**」

→ ★ **这是选型的硬约束：球形世界和自由旋转相机有冲突。**
本项目是**轨道相机**（`camDistance` / `camHeight` / 鼠标转视角），
相机角度是玩家自由控制的 → **必须做视锥剔除的修正**，否则会看到物体突然消失。

## 四、★ 与本项目的对照

### 4.1 好消息：项目已经是「视觉与碰撞分离」架构

`SpiderProxy`（无渲染器碰撞体）+ 完整蜘蛛视觉体——**球形世界天然契合这个架构**：
视觉可以是球面，碰撞保持实际几何，两者互不干扰。

### 4.2 ★ 关键冲突：球心跟相机 vs 跟玩家

教程里距离是 `物体 − 相机`，球心跟着**相机**。
但本项目的玩家是**会离开地面的**（摆荡、冲刺、跳跃）。

→ 球心跟相机 = **玩家爬上天花板时，地面会在他脚下卷起来**。
→ ★必须改成跟**玩家**，或者更准确：跟玩家在「当前表面」上的投影点。

### 4.3 ★ 与表面移动系统的关系

`SilkSpiderSurfaceMove.cs` 里：

```csharp
public Vector3 SurfaceNormal { get; private set; } = Vector3.forward;
SurfaceNormal = hitInfo.normal.normalized;   // 射线命中法线
```

→ **法线来自射线命中的碰撞体，不是渲染网格。**
→ 视觉卷成球面后，**视觉法线与碰撞法线会不一致**——
球心远的一侧视觉上应该是斜的，但碰撞体还是平的。

★ 这不是 bug，是必须选一个：
| 方案 | 做法 | 后果 |
|---|---|---|
| A. 只卷视觉 | 玩家感觉地面弯了，但碰撞是平的 | 远处站位与视觉有偏差，走快了会有「滑下去」感 |
| B. 视觉+碰撞都卷 | 碰撞网格也生成弯曲版本 | 成本高，且网格变形会破坏体素网格对齐 |

★ **对本项目建议A**：因为玩家主要在近距离活动（房间 7m），
视觉弯曲是「远景观感」需求，不是玩法需求。近处 R 大 = 几乎不弯。

### 4.4 ★★ 体素网格的对齐问题（本项目独有）

`VoxelGrid.size = 160`（±80格，1米 = 5格）。

→ **顶点着色器位移会破坏体素对齐**。
→ 如果位移在 shader 里做，CPU 侧的体素坐标仍然是平的世界坐标
→ ★ **摆荡锚点、丝线落点、跳跃判定全部继续用平坐标**，
这反而是好事——**物理与摆荡一行都不用改**。

## 五、结论：这个方案对项目的适配判断

### 5.1 为什么用户判断「这个应该好做」是对的

| 对比项 | 重力切换（Control） | 球形世界 |
|---|---|---|
| 改物理 | **必须** | **完全不用** |
| 玩家适配 | 有认知负担（有人晕 2 小时） | 几乎无 |
| 认知参照 | 要建立「局部地板感」 | 保留原有上下 |
| 实现面 | 玩家控制器 + 敌人 AI + 相机 + 关卡 | **只有一个材质** |
| 可撤销 | 难 | **删掉材质函数即可** |

### 5.2 ★ 但有三个本项目特有的坑（视频和 UE 教程都没有）

1. **视锥剔除 + 自由轨道相机** → 物体会突然消失（kianbennett 明确警告过这个组合）
2. **法线必须同步旋转** → 否则光照假
3. **球心跟相机会导致玩家离开地面时地面卷起** → 必须改成跟玩家

### 5.3 最小可行路径

```
第1 步：写一个最小的 Built-in 管线 shader（不是 URP，本项目是 Built-in）
         只做完整球面公式，一个 Plane 网格，一台固定相机
         → 验证数学正确

第 2 步：加球心跟随玩家，加 Power / FlatDistance / BaseDistance 三个全局参数
         → 验证动态

第 3 步：扩 bounds 处理视锥剔除，加法线旋转
         → 消除两个「看起来很假」的问题

第 4 步：接入 HouseBlockout 的材质，R 调大到房间尺度内几乎不弯
         → 只保留远景观感
```

★ **成本估计：shader 半天到一天，第 3 步的 bounds 是主要不确定性所在。**
Unity 里有现成做法但需要实测验证。

## 六、可直接抄的三个设计决策

1. ★ **用 MPC / 全局 shader 参数而不是改材质**
   一次修改全场生效——这与项目里「参数全部接线、无悬空旋钮」是同一条纪律。
   **每个物体用自己的材质实例 = 几百个材质 = 改一次参数要改几百次。**

2. ★ **Pivot 必须对齐到参考物体的位置**
   UE 里 pivot 相对偏移会让整个网格平移。
   ★ 这是一个「不做就会看到明显错误，但不知道原因」的坑。

3. ★ **顶点细分不能省**
   教程明确设 50。细分不够 → 弯曲后是折面而不是球面。
   ★ 本项目体素网格是天然的细分充足，但要注意**球心在远处时
   一个大格子跨越的弧长会变明显** → 远处需要额外细分。
