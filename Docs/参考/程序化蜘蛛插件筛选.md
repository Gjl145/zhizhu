## 二、★ 核心技术对比（本项目最关心的）

| 维度 | Procedural Spider | Legs Animator | 本项目 |
|---|---|---|---|
| IK 算法 | **定制 CCD**（循环坐标下降） | 内置 IK 或接Final IK / Mecanim Foot IK | **FABRIK** |
| 换点判据 | ★ **「IK 解不动了就换点」**（带容差） | 距离阈值（`Step Distance`） | **「IK 解不动就换点」** ✅ |
| 异步编排 | ★ **两种approach 并存**（见下） | `Other Foot` 字段指定互斥腿 | 相邻互斥 + **今天刚改成可配置** |
| 换点预测 | ★ **锚点 + 预测位移 + 多向射线找面** | 向前投影 | 有 `maxPredictLength` |
| 身体位置 | ★ **由足端平均位置反算**（Smart Body Position Box） | `Hips stability` | 有 `bodyBobAmount`，但非足端反算 |
| 关节限位 | ★ **每节有旋转上下限**（hinge joints） | 未提及 | **❌ 没有** |
| 地形拓扑理解 | ★ 向**下/向外/向内**多向射线 | 未提及 | 单向 `footRay` |
| 爬墙 | ★ 球cast（向下调地形 + 向前爬墙）+ **假重力** | 无（纯贴地） | ★ 已有（`SilkSpiderSurfaceMove`） |
| 腿数 | 8（每腿 5 节 + 末端执行器） | 任意 | 8 × 5 节 ✅ |
| 动画混合 | ❌ **完全程序化，无法混合动画片段** | ✅ **可与已有动画同步工作** | 无动画片段 ✅ |

## 三、★★ 本项目适配判断

### 3.1 ★★ 直接用插件是错的，三个硬冲突

| # | 冲突 | 说明 |
|---|---|---|
| **1** | **坐标系统** | 本项目 **Z-up**（X=左右 Y=前后 Z=高度）。候选 A 官方明确写「our model is actually rotated 90 degrees」。Legs Animator 推荐 **Z-Forward** 但没说Z-up 上方向 |
| **2** | **它会接管角色控制** | 两个插件都自带**完整角色控制器**（移动/相机/跳跃）。本项目已有 `SilkParkourController` + 8 键硬规则+ 摆荡系统。装了就是**两套控制器抢同一个物体** |
| **3** | ★ **丝线摆荡会被破坏** | 插件是「身体控、腿跟随」。本项目是**球体碰撞 + 丝线摆荡 + 八足 IK**。摆荡时球在空中无支撑，落点解算的假设全部失效 |

### 3.2 ★ 但有三个机制**值得直接抄进现有代码**

以下都不需要引入插件，只需改现有实现：

#### ① 「IK 解不动就换点」—— 本项目已用，但要看清它和 A 的差别

候选 A 的原话：
> 「A leg desires to step if the IK solver **can not solve the leg sufficiently anymore**,
> that is up to a set tolerance.」

★ 本项目 `check_gait_convergence.py` 抓的「移动两步就重来」正是这一环。
**我们的判据应该对齐这条**：不是「距离超过阈值」，而是「**FABRIK 收敛残差超容差**」。

#### ② 身体位置由足端平均位置反算（Smart Body Position Box）★ 最值得抄

视频专门把这个功能拎出来说「makes everything more realistic」。

★ **本项目当前的 `bodyBobAmount` 是固定振幅**，而 A 是：
```
身体高度 ← 8 个足端的高度均值
身体朝向 ← 足端位置的分布
```
→ 好处：**站上球面时身体会自己倾斜**，不需要额外逻辑。
→ 本项目**已经有 8 个足端坐标**，实现成本极低。

#### ③ ★ 关节旋转限位（rotational limits）—— 本项目完全没有

候选 A：每条腿是 **chain of hinge joints with implemented rotational limits**。

★ 本项目 FABRIK 求出的关节角**没有任何上下限**，
→ 意味着**腿可以往反方向拧**（比如膝盖反向、腿穿过身体）。
→ 这是「看起来很假」的一个隐藏来源。

## 四、★ 采购建议

### 结论：**先不买。先抄三个机制。**

理由：

| 论据 | 说明 |
|---|---|
| **价格** | $79.99 + $43.99 = **$124**，两个都买 |
| **冲突** | 两个都会自带角色控制器，与本项目 `SilkParkourController` 冲突 |
| **替代性** | 本项目 FABRIK + 交替四足 + 互斥可配置 + 爬墙，**核心已经齐了** |
| ★ **开源版可读** | PhilS94 的 GitHub 版是**同一套机制的完整源码**，免费，先读它 |

### 具体行动

| 优先级 | 行动 | 成本 |
|---|---|---|
| **P0** | 跑一次 Unity 看 `DescribeLegs()` →验 FBX 朝向（**必须 0/8**） | 0 |
| **P1** | ★ 抄「身体位置由足端均值反算」 | 半天 |
| **P2** | ★ 抄「关节旋转限位」→ 给 FABRIK 加上下限 | 1 天 |
| **P3** | 读 `PhilS94` GitHub 的换点预测（锚点 + 预测位移 + 多向射线） | 1~2 天 |
| **可选** | 真需要**多只 NPC 蜘蛛**（比如敌人）→ 考虑买 `Legs Animator`（$43.99，评分 4.9，且支持与动画混合） |

★ **唯一值得买插件的场景**：本项目要做「一群蜘蛛 NPC 当敌人」。
因为那时需要**别人的成熟控制器 + 性能优化**，而本项目自己写第二套 AI 不划算。

## 五、Legs Animator 的一个已知坑（官方自己写的）

> 「**Not working with Unity's Animation Rigging Package "Two Bones Constraint IK"**:
> Animation Rigging is discarding source animation before LateUpdate,
> making impossible to control "Two Bones Constraint" by Legs Animator.」

→ 就是 IK 教程里那个 `TwoBoneIKConstraint`。若买Legs Animator，**别同时用 Animation Rigging 的 TwoBoneIK**。

## 六、抄机制时的三条硬约束（本项目专属）

| 约束 | 来源 |
|---|---|
| **Z-up**：表面法线即「上」 | 记忆里已锁定 |
| **8 键硬规则**：不新增按键 | 用户明确锁定 |
| **无死代码**：所有参数必须接线 | 项目纪律 |

★ 抄「关节限位」时会碰到一个问题：**限位值从哪来？**
→ 答案不能编：应从 Blender 侧的骨骼 rest pose 反推（把 rest 姿态的局部角度当 0，
在它基础上± 一个范围）。这需要改 `make_spider.py` 导出限位表，
或者在 Unity 首次运行时从 FBX 的骨骼 rest 姿态自动采样。
→ **不要手写魔法数字。**
