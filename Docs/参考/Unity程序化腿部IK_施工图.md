## 零、教程的核心洞见（先讲这个）

教程第一句话就点明了架构的关键：

> 「**并不是角色的腿部来自身起身体**。玩家实际上控制的是角色的身体部分。」

★ **这句话是整个方案的地基**：腿不是角色的附属物，**身体才是被腿撑起来的**。
→ 推论：身体移动时腿的落点**必须保持不动**（这是本项目 `check_gait_convergence.py`
   在抓的那件事）；支撑腿不移动，IK 只负责把腿「拉」到落点。

## 一、完整流程（8 步）

### 步骤 1~4：模型与骨骼准备（Blender 侧）

| 步 | 做什么 | 关键点 |
|---|---|---|
| 1 | Blender 里搭几个长方体拼一个四足生物 | 教程用极简长方体，**不是正式模型** |
| 2 | **设置身体与腿的父子关系** | ★ 骨骼链的根基 |
| 3 | ★ **腿的原点保持在根部位置** | 关节 pivot 必须在关节上，不在几何中心 |
| 4 | 导出 FBX | |

★ 第3 条正是本项目记忆里那条「pivot 必须对齐」的同一个坑。

### 步骤 5：Rig Builder 生成骨骼

| 步 | 操作 | 结果 |
|---|---|---|
| 5a | 选中模型 → 菜单 `Rig Builder` → `Setup` | 生成类骨骼结构 |
| 5b | ★ 「骨骼只延伸到膝盖」 | 因为建模时**没做脚掌** |
| 5c | ★ **在脚末端创建空对象表示脚掌位置** | 4 个脚掌都建 |
| 5d | 重新 `Setup` | **骨骼覆盖全身** |

★ **这是个反复出现的坑**：「末端没有目标 → 骨骼少一节 → IK 无解」。
本项目对应：`SilkSpiderFbxRig` 要求每条腿 **5 节骨骼齐全**，缺一节就报错——
这与教程「建好脚掌再重新 Setup」是同一条经验。

### 步骤 6：Animation Rigging 的 TwoBoneIK

| 操作 | 说明 |
|---|---|
| 选中角色 → `Animation Rigging` → `Leg Rig Setup` | 自动为每条腿生成一个 IK 对象 |
| 该对象位置**归零** | |
| 在它下面建空对象，命名如 `LegBone_1` | 用来挂这条腿的控制脚本 |
| 给它加 **TwoBoneIKConstraint** 组件 | ★ Unity 官方包 |
| `Tip` 字段 | 拖入**该腿的脚掌**（末端目标） |
| 点`Auto Setup` | ★ **自动识别大腿 + 小腿** |
| 之后自动创建 `Target` 与 `Hint` | |

★ **`Target` = 腿要伸向的目标**
★ **`Hint` = 膝盖要弯曲的方向**

> 「右下角这里可以让它显示一个标识」—— 编辑视图里可视化，便于调试。

### 步骤 7：Target 控制脚本（★ 核心）

挂在这个腿的 `LegBone_N` 上。

#### 参数（教程逐项说明）

| 参数 | 含义 | 本项目对应 |
|---|---|---|
| `body` | 身体 Transform | 已有 |
| `ground collider` | 地面碰撞体（叫它放哪） | **`VoxelGrid`** |
| `spacing 1` / `spacing 2` | 落地点相对**身体中心**的偏移（X 前后 / Z 左右） | 8 条腿各一份偏移 |
| `step Distance` | 脚移动时的抬起高度 / 速度 | 见下|
| `leg 1` / `leg 2` | ★ **不能同时抬起的腿**（互斥腿） | **已有：`dutyFactor` 相邻腿互斥** |
| （另有设置面板） | |

★ **`leg 1` / `leg 2` 是这个教程最值钱的设计**：

> 「这里设置的是**不会同时抬起的脚**。如果同一行或者同一列的脚同时抬起显然是不合常理的。」

→ 这与本项目已实现的「相邻腿摆动互斥」是**同一个机制**，
但教程的表达更通用：**可以给每条腿指定任意两条互斥腿**，
而不是硬编码「相邻互斥」。

### 步骤 8：地面 + 身体倾斜脚本

| 步 | 操作 |
|---|---|
| 建地板 | **必须加 Collider**（要射线检测） |
| 地板设个颜色 | 便于区分 |
| 身体倾斜脚本 |挂身体 + **加 Rigidbody + 关掉重力** |

★ **身体倾斜原理（教程原话）**：

> 「原理就是检测角色下方地面的斜率，然后调整身体的斜率与其一致。
> 另外的方法还有**根据四条腿的高度差来计算身体的斜率**。」

★ 两种算法，本项目应该用第二种（腿高度差）——因为本项目**已经有 8 个足端坐标**，
不需要额外射线，而且能天然处理「站在球面上」这种情况。

## 二、Update 的完整逻辑（照着复刻的规格）

```
射线起点 = 身体位置 + spacing 偏移
射线方向 = 往下
  ↓
检测射线是否与地形碰撞
  ↓
判断「落点与检测点的距离」是否超过阈值
  ↓
同时检查 leg1 / leg2 是否正在抬起（互斥）
  ↓
开始移动动画 → 把 Target 射线到新位置
  ↓
抬升函数 = 三角函数（山弧线）作为移动路径
  ↓
一般状态：保持位置不动
```

★ **落点偏移必须按轴分别设置**。教程踩过这个坑：

> 「设置完成后我们会发现，脚的目标都跑到了身体的中心位置，
> 这是因为我们还没有设置偏移，四个角的检测射线都在身体的中心。」

→ 修法：设置好一个角的偏移后，**复制到其他三个角并加对应的正负号**。
★ 本项目 8 条腿 = 4 个角 × 左右，完全适用同一套路。

### 教程明确提到的一个坑

> 「注意的是模型的方向和代码的方向是不一样的，因为我们导入的模型实际上是导Z 的，
> 它在场景里实际上旋转了90 度，所以代码里要注意一下它的方向。」

★★ **这条直接命中本项目**：`orientationFixDeg = 90` 就是同一件事，
而且本项目至今是推导值、未实测。

## 三、逐条对照本项目：已有什么 / 要做什么

| 教程要素 | 本项目现状 | 判断 |
|---|---|---|
| 身体控制，腿不控制 | ✅ 已是这个架构 | **一致** |
| 落点保持不动（支撑相） | ✅ `dutyFactor = 0.65`，`check_gait_convergence.py` 在验证 | **一致，且有测试** |
| 抬升用三角函数弧线 | ✅ 已有摆动相划弧线 | **一致** |
| 腿互斥 | ✅ 相邻腿互斥 | ★ **可升级**：改为每条腿可指定任意两条互斥腿（教程的 `leg1/leg2`） |
| 身体按地面斜率倾斜 | ⚠️ 待查 | ★ **本项目已有更优解**：用8 个足端高度差算斜率 |
| TwoBoneIKConstraint | ❌ 没用，用自写 FABRIK | **不需要换** ——FABRIK 对多足更合适（IK 插件是双足专用） |
| Rig Builder 自动生成骨骼 | ✅ Blender 侧已有 42 骨骼 | **不需要** |
| 落点偏移 | ✅ 已有 `LEG_YAW_DEG` 等 | **一致** |
| 模型方向 90° | ⚠️ `orientationFixDeg = 90` 未实测 | ★ **必须实测**（判据见下） |

### ★ 为什么不该换成 Animation Rigging

教程用的 `TwoBoneIKConstraint` 是**双足专用**（一条大腿 + 一条小腿 + 一个 Tip）。
蜘蛛是 **8 条 × 5 节**，硬套 8 个 TwoBoneIK 会有两个问题：

1. **5 节骨骼 vs 2 节**：TwoBoneIK 只能解2 段，本项目是5 段
2. **8 个约束体 × 5 次迭代 = 40 次/帧**，而FABRIK 一次性解 8 条链

★ **结论：保留 FABRIK。** 教程的架构（身体控、落点锁定、互斥、三角弧线）
本项目全部已有且更完善。**唯一值得照搬的是「腿互斥从硬编码改为可配置」。**

## 四、★ 唯一要照着做的改动：腿互斥可配置化

### 现状
```csharp
// 相邻腿摆动互斥（两趟法裁决）
// L1=0.00 L2=0.50 L3=0.00 L4=0.50 / R1=0.50 R2=0.00 R3=0.50 R4=0.00
```
→ 「相邻互斥」是**硬编码**的相位表。

### 教程的做法
每条腿挂 `leg1` / `leg2` 两个字段，指定**不能同时抬起的腿**。
> 「如果有更多需求的话可以在后面继续加。」

### 改成
```csharp
[Tooltip("★ 与本腿互斥、不能同时摆动的另外两条腿（0=禁用）。\n"
    + "教程做法：leg1 / leg2 两个字段。\n"
    + "同侧相邻腿必须互斥（解剖上会撞），跨侧可自由配置。")]
public int[] exclusiveLegs = new int[2];   // 每条腿一份
```

★ **为什么这对蜘蛛特别重要**：蜘蛛 4 对腿分布在同一侧，
「相邻互斥」只保证左右交替，**没保证同侧两条腿不会同时抬起**。
真实蜘蛛同侧的腿是**对角步态**（左1+右3 同时，左2+右4 同时），
这个必须可配置才能表达。

## 五、实测判据：FBX 朝向

教程踩的「模型旋转了 90 度但代码方向不对」=本项目的 `orientationFixDeg`。

★ **判据已在代码里备好**：`SilkSpiderFbxRig.DescribeLegs()`
统计「足端高于腿根的腿：N / 8」。
重力沿 −Z，**正确结果必须是 0 / 8**。

若不是 0/8 → 调 `SilkSpiderAnatomy.fbxOrientationFixDeg`（当前 90），
或试 0 / 180 / 270，直到 0/8。

   教程踩了才发现。→ 本项目已有偏移配置，但值得在HUD 里显示出来自查。
