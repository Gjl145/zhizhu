# 今日操作说明 · 蜘蛛假骨骼（2026-10-09 晚间修正版）

> 用户反馈：「之前运行的时候什么都没有看到，包括蜘蛛或者场景什么的。」
> 复查后发现**共 7 个独立根因**（上一版只认出3 个）。
> 本版重点：**先确认运行的是哪个场景**，以及每一步该看到什么。

## ★★★ 第0 步：确认你打开的是哪个场景（最容易踩的坑）

项目里有**两个**场景文件：

| 文件 | 内容 | 说明 |
|---|---|---|
| `Assets/Scenes/SampleScene.unity` | 只有 `bossbattle`（挂 SilkBuilder） | 老场景 |

但为了看清效果，**推荐用 `Assets/ceshi.unity`**。

Unity 窗口顶部中间会显示当前场景名 —— **先看这个**。

## ★ 你只需要做两件事

### 第 1 步 —— 让 Unity 重新编译

**资源（Assets） → 刷新（Refresh）**，或按 `Ctrl + R`

> 改完代码 Unity 不会自动重编。**这是最常见的「改了没反应」原因。**

### 第 2 步 —— 点播放（Play），然后按一下 `Tab`

会多出一个**黑色扁球**，下面伸出 **8 条深色腿**在地板上交替迈步。

| 操作 | 按键 |
|---|---|
| 转视角 | 移动鼠标 |

| 跳 | `空格` |
| 冲刺 | `左 Shift` |
| 切模式 | `Tab` |

让球撞到墙上→ 腿应该转到朝上、贴着墙走。
走到台阶上 → 腿应该抬高再落下。

### ★ 为什么必须按 Tab

```csharp
SilkControlMode mode = SilkControlMode.FreeFly;      // 初值FreeFly
if (mode == SilkControlMode.Parkour) { CreateVisual(); }  // 球只在这建
```

FreeFly 是「编辑器世界/ 织网」，球属于「跑酷世界」——
FreeFly 下**刻意不建球**。这是项目原有设计，不是 bug。

## 本次复查新发现的 4 个根因（前一个是前一次发现的）

### 根因 4 ★★ 场景里根本没有 SilkBuilder

我上次把宿主定为「遍历 `FindObjectsOfType<SilkBuilder>()`」——
但 **`ceshi.unity` 里一个 SilkBuilder 都没有**（连一个 MonoBehaviour 都没有）。
→ 数组长度 0 → 循环体不执行 → 测试场永远建不出来。

**修法**：三级兜底宿主策略
① 已有 SilkSpiderTestStage → 复用
② 已有 SilkBuilder → 挂在它身上
③ **都没有 → 自己 new 一个 `SpiderTestHost`**

### 根因 5 ★★ 相机存在，但**没在看测试场**

`ceshi.unity` 里**是有相机的**（Main Camera 在 `(0, 1, -10)`），
所以旧写法 `if (cam == null) { 建相机 }` 整段被跳过。

但那个相机是**Unity 默认 Y-up摆放**的，朝 −Z 看。
而本项目是 **Z-up**，测试场在 Z = 0~14 的高度上。
→ **相机存在，但完全没在看测试场。**

场景里那两个物体也说明了问题：

| 物体 | 位置 | 离原点 | 可见？ |
|---|---|---|---|
| Cube | (2, 101, 86.5) | 139 格 |勉强 |
| Sphere | (41152, 166.5, 114044) | **12 万格** | **远裁剪面 1000 之外，永远不渲染** |

**修法**：`EnsureCameraAndLight()` 改成**存在也强制摆位**，
摆到 `(0, -26, 16)` 朝原点（Z-up）。用 `cameraPlaced` 标记只摆一次，
免得Start 里二次覆盖你调好的视角。

### 根因 6★★ `SilkSpiderTestStage.Awake()` 里的 `if (builder == null) return;`

宿主 `SpiderTestHost` 上本来就没有 SilkBuilder（那时还没补建），
于是**每一次都命中这个 return** → 下面的 `Build()` 永不执行。

**修法**：`builder` 拿不到就用 `FindObjectOfType<SilkBuilder>()` 兜底，
再拿不到就**只跳过那两个开关设置，照常建测试场**。

### 根因 7 ★★ 最容易崩：宿主没有 SilkBuilder → 一按Tab 就崩

控制器的 `builder` 来自 `FindObjectOfType<SilkBuilder>()`（`SilkBuilder.cs:4465`）。
场景里没有 → `builder` 全程null → 而这些地方**完全不做 null 检查**：

| 行号 | 代码 | 何时崩 |
|---|---|---|
| 4508/4509 | `if (builder.freeBuildSpawnOverride != ...)` | `DetectFreeBuildSpawn()` |
| 4522 | `new Vector3(500, 500, builder.freeBuildSearchMaxZ * .5f)` | 同上 |
| 4538 | `if (top <= builder.freeBuildSearchMaxZ)` | 同上 |
| **4561** | `=> builder.freeBuildMode ? ... : ...` | **`EffectiveStartPosition`** |
| **4566** | `=> builder.freeBuildMode ? ... : ...` | **`EffectiveFallRespawnZ`** |

★ 4561/4566 正是**切 Tab 时控制器决定球往哪放**的入口。
→ 一按 Tab 立刻 `NullReferenceException`。

**修法**：建宿主时**同时补一个 SilkBuilder**。
安全性已核对：`Awake` 只有「实例唯一性守卫」（场上本就没别的，不触发），
`Start` 只设两个 LayerMask（无副作用）。

### 附带修：hideFlags 用错

`HideFlags.HideAndDontSave` 带 `DontSaveInEditor | DontSaveInBuild`，
物体**不参与构建**；与 `DontDestroyOnLoad` 混用行为不可靠，
切场景后 watcher 可能静默消失 → 腿再也补挂不上，且**无任何报错**。

改为 `HideFlags.DontSave`（只影响保存，不影响运行时生命周期）。
宿主也设上，防止它被存进场景文件。
