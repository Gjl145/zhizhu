### 1.2 ★★★ 六个必须记住的坑

#### 坑 1：足部射线起点不能放在「脚的正上方」

**作者的原话**：
> "there's an issue with the foot IK and it's caused by tracing from straight above the foot to straight below but **the leg's not actually coming from straight above or below**... where if it goes over an edge it can snap down and the leg will actually intersect the geometry"

**问题**：射线是垂直的，但腿是斜着来的。脚越过边缘时，垂直射线打到的位置和「腿实际能到的范围」不匹配 → 腿插进几何体。

**修正尝试 1（失败）**：把射线起点移到骨盆正上方 →
> "did not help"

**修正尝试 2（成功）**：**在两者之间插值**
> "we're going to interpolate between these two vectors... so that's halfway between straight above the pelvis and straight above the foot"

**对我们的意义**：假骨骼的落点射线起点应该在 `骨盆上方` 与 `脚上方` 之间按比例插值，
而且这个比例要调。写死任何一个都会在边缘处出问题。

#### 坑 2：速度投影必须在 trace **之前**

**作者的原话**：
> "what we should be doing is **projecting the end point** and then doing the trace to see where the end point actually hits the floor"

**错误做法**（他先做的）：
```
脚当前世界位置 → trace 打点 → 命中点 + 速度向量 = 新落点
```
→ 腿移动时穿进地面，因为「加完速度」的位置根本没有验证过有没有地面。

**正确做法**：
```
脚当前世界位置 + 速度向量 = 投影点 → 从投影点上下 trace → 命中点 = 新落点
```

> "now you can see that the feet are always actually meeting the floor when it's moving"

#### 坑 3：world space ↔ rig space 转换时容易骗自己

**作者的原话**：
> "we can assume that we've done something wrong in terms of switching from worldspace to global space... **we named the variable previous world location but we're not actually converting it to a world location, we're just getting the global transform of the bone**"

命名误导：变量叫 `previousWorldLocation`，实际上只是 `bone.globalTransform`。
在 UE 里 rig space ≈ Unity 的 local space，在骨骼层级里逐级相乘就是 world。

**正确做法**：
> "if you drag out from **Translation → To World** and plug that into the subtract"

**在我们的 Unity 里**：`bone.position`（不是 `bone.localPosition`）才是世界位置。
`worldPosition = bone.position`，反过来 `bone.position = worldTarget`。

#### 坑 4：所有腿同时动 —— 因为相位没错开

**作者踩了两次坑才解决**：

**第一次**：所有腿的 timer 都从 0 开始，同时增长、同时到顶、同时重置 →
> "all the feet are moving at once and that's because we... are setting the array element to 0 for all the feet and we're increasing them all at the same time"

**修法（相位错开）**：
```text
footTimings[i] = i / 8      // i 是腿的序号，8 是总腿数
```
> "which is an eighth of a second, so **each leg will be offset by 0.125**"

**第二次**：距离触发的重置把所有腿又拉回同步
> "if they all reset at once because it's moved too fast they all get reset on the same timer so the legs become in sync and so they no longer offset"

**修法：距离触发重置时，不是设 0，而是设一个随机偏移**
```text
footTimings[i] = random(min, max)     // 用 i 作随机种子，保证每条腿不同
footTimings[i] = 0                    // 正常计时到点重置才用 0
```
> "even though the legs are moving out of their range at the same time they still stay out of sync because we've added some randomness to it"

★ **这段是整段视频最有价值的部分之一**。开源项目用
`AlternatingTetrapodGait` 枚举解决同一问题，但没讲「距离触发会导致同步」这个坑。

#### 坑 5：`clamp` 不够，要用 `Remap`

**问题**：用 `clamp(timer, 0, 1)` 得到 0→1，但 t 到 1 之后一直卡在 1，
而目标是「持续往新位置走」，结果脚「一直在原地抖」。

**修法**：`Remap(0 → 0.2)` —— t=0 时 alpha=0，t=0.2 时 alpha 已经到 1。
**在 1/5 的时间里走完全程。**

> "so now the feet move a lot faster because in a fifth of the time they're moving the full distance"

#### 坑 6：速度太快时腿会被甩出去 —— clamp 速度向量长度

> "the legs are sometimes stretching out too far so when we do get calculated velocity we're going to **clamp the length of that vector** so that it limits how far it can sort of predict the legs forward"

他先用 `1200`（UE5 单位 = 厘米，即 12 米），并说：
> "we might want to reduce that later... but for a normal movement speed that's not the main issue"

### 1.3 ★★★ 完整算法（可直接翻译成 C#）

**每一帧依次执行：**

```text
1. IncreaseFootTimings(dt)
   for i in 0..7:
       footTimings[i] += dt * speedScaleFactor

2. 骨盆球形 trace
   从骨盆 +150Z 到 -150Z，Sphere Trace by Channel
   命中点 → Set Bone Transform (Pelvis)
   ★ 但不是硬 set，是 Spring Interp：
     savedPelvisOffset → SpringInterp(saved, target, strength, damping)
     他最终用 strength=2, damping=0.5（说 0.5 有点 Q 弹但"能吸收一些下坠的重量"）
   ★ 还要加大 sphere trace 半径，否则骨盆会插进地面

3. CalculateVelocity
   velocity = (boneCurrentWorldPos - bonePreviousWorldPos) / dt
   用 lerp(0.1) 平滑
   ★ 原因："if we use a number like 0.1 all the time it'll accumulate
     and get closer and closer to the actual value"（0.1 是插值因子不是直接乘）

4. CalculateNewFootTargets
   for i in 0..7:
       // 距离判据：脚离它「想去的位置」太远就强制重置
       dist = |footBone.position - lockedFootLocation[i]|
       tooFar  = dist > 1200
       timedOut = footTimings[i] > 2       // 2 秒
       if tooFar || timedOut:
           lockedFootLocation[i]   = targetFootLocation[i]   // 旧目标变锁定点
           targetFootLocation[i]   = footBone.position + clamp(velocity, 0, 1200)   ★ 加速度在 trace 前
           footTimings[i]          = tooFar ? random(-0.125, 0) : 0
           // ★ 距离触发用随机偏移，计时触发用 0

5. 抬腿弧线（在 IK 之前）
   liftHeight = curve.Remap(footTimings[i], 0→0.2, 0→maxLift)
   ★ maxLift 按速度 remap：speed 0 → 0，speed 400 → 150
     "so now when we simulate the legs aren't lifting when it's stationary
      but when it moves the legs are lifting"

6. Basic IK 逐腿
   target = lerp(lockedFootLocation[i], targetFootLocation[i], Remap(footTimings[i], 0→0.2))
   target.Z += liftHeight
   ★ trace 起点 = lerp(骨盆上方, 脚上方, 0.5)   ← 坑 1
   ★ trace 从起点上方 50 到下方 50

7. CalculateAverageFootLocation
   avg = Σ footBone.position / 8
   ★ 骨盆的目标改成 avg（不是 pelvis 自己的位置），也走 Spring Interp
```

### 1.4 ★ 作者自己承认的局限

> "it's not perfect but at least when it's moving at low speeds it kind of holds up and if you do some weird direction changes it probably won't"

> "there's no way that the legs are going to make sense when it's moving that fast"

> "there's probably better ways to do it but what I'm going to do is..."（用随机偏移打补丁）

★ **重要判断**：这是**快速原型级**方案，不是成品方案。作者用了至少 6 次
「试一个值 → 不行 → 改」才做出来，而且最终步态是靠随机数维持不同步的。
我们做假骨骼时可以**借鉴流程，但不必抄他的具体数值**（UE5 单位是厘米）。

## 二、90 秒 Unity 蜘蛛侠案例

**BV 号**：`BV1fV5szDEuU`
**时长**：90.8 秒

### 2.1 抽帧发现

| 帧 | 内容 |
|---|---|
| u03 | 工程名 `ThirdPersonProject`，字幕「向量坐标吸附系统」，角色是有骨骼的蜘蛛侠（红蓝人形），在两栋建筑间摆荡 |
| u15 | 可见多条丝线，**丝线是分段折线**（`LineRenderer`），角色悬挂其上 |
| u25 / u52 | 建筑间摆荡，丝线落在建筑表面 |
| **u70** | **★ 角色整个贴在墙面上横向移动** |
| u80 | 角色站在一根水平丝线上（走钢丝） |
| u87 | 角色贴墙移动 |
| **u90** | **★ 角色是「蹲姿、四肢着地」的爬行姿态，身体压得很低、腿朝侧面张开** |

### 2.2 ★ 两个结论

**结论 1（印证用户直觉）**：
> 「蜘蛛的攀爬是不是不需要这么多的东西，好像可以直接去抓住墙面攀爬」

**成立**。u70 帧清楚显示角色整个贴在墙面上，**没有任何抓边动作**。
人形攀爬状态机那套东西（边缘检测、空间检查、换手）对它不适用。

**结论 2（补充，之前的判断有误）**：
我之前只看到 u70 得出「贴墙爬」的结论，但 **u90 帧显示这是蹲姿四肢着地的爬行**，
**不是攀爬竖墙**。身体压低、腿朝侧面张开 —— 这是蜘蛛的本体姿态，
贴墙只是这个姿态在墙上的表现。

★ **这直接决定假骨骼的形态**：不能做成「人站立 + 手扶墙」，
必须做成**身体离地很近、腿朝两侧张开**的姿态。否则在墙上会像壁虎而不是蜘蛛。

### 2.3 丝线的实现方式（顺带确认）

**分段折线 + `LineRenderer`**，不是连续的圆柱。u15/u25/u52 三帧都能看到明显的折点。
这和我们已知的 `SilkLine` 做法一致（分段 + 关节），无需改动。

## 五、对假骨骼的直接影响（写给等下的自己）

### 5.1 姿态（来自 90 秒视频 u90 帧）

- 身体**贴近表面**，不是直立
- 腿朝**左右两侧**张开，不是前后
- 所以「前进方向」和「腿展开方向」是**垂直**的
- 在墙面上：身体贴墙，腿沿墙面左右展开，沿墙面上下交替

### 5.2 顺序（来自 UE5 视频完整流程）

```
Update:
  1. 身体已经在移动（SilkSpiderSurfaceMove 管）
  2. 算速度（球的世界坐标差分 + 平滑）
  3. IncreaseFootTimings(dt)
  4. CalculateNewFootTargets   ← 加速度在 trace 之前
  5. CalculateAverageFootLocation
  6. 抬腿弧线 → 目标点
  7. trace 落点
  8. 摆腿（朝向目标 + 抬腿高度）
```

### 5.3 必须避免的三个已知的失败模式

1. **腿插进几何体** → 射线起点必须在骨盆上方与脚上方之间插值
2. **8 条腿同步跳动** → 相位必须错开，且距离触发重置时用随机偏移
3. **静止时也在原地踏步** → 抬腿高度必须乘速度因子

### 5.4 与我们现有代码的接口

| 需要的东西 | 现有来源 |
|---|---|
| 表面法线 | `SilkSpiderSurfaceMove.SurfaceNormal` |
| 是否贴面 | `SilkSpiderSurfaceMove.IsGrounded` |
| 球半径 | `SilkParkourController.visualRadius` |
| 速度 | `SilkSpiderSurfaceMove.CurrentVelocity` |
| 球形射线 | `SilkSphereCast`（已写好） |
| 自身 Collider 排除 | `SilkSphereCast.SetIgnore` |

★ 六项全都有。假骨骼可以直接写，不需要动 `SilkBuilder.cs` 一行。
