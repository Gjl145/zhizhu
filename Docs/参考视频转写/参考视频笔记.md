## 视频 1：基于瞬移能力的关卡练习（画面分析）

⚠️ **该视频音轨为静音**（实测 mean_volume = −91 dB，35 kbps 音轨），

### 这是什么

Unity 官方风格的「传送（Teleporter）关卡练习」——
用最基础的传送能力，练习**跳跃 + 传送的衔接**。

### ★ 最重要的一条：光线引导（5:30-7:00 段落）

视频字幕直接点明：「右侧破损的窗户和光线引导探索」。
配合画面能看到：房间是封闭的暗色调，**右侧有一处破损的窗户透进光柱**，
玩家的注意力被自然引向那个方向。

这是线性引导（linear light flow）的经典用法：
- **暗环境 + 单一光源** → 玩家的视线自动被光吸引
- **破损的窗户** = 「这里可以过去」的暗示
- 不需要任何 UI 箭头，靠场景本身说话

**→ 对应我们的项目（这是最该学的一条）**：
我们的关卡是「灰蓝平地 + 蓝高台 + 绿窄道 + 黄终点」，
全靠**颜色区分**。但问题是：
- 场景本身没有视觉引导，玩家不知道该往哪看
- 所有平台在同一亮度层次上，没有「主次之分」

**可以借鉴的做法**：
1. 让**终点方向更亮**（光源或自发光），形成视觉焦点
2. 在平台上加**指示方向的元素**（如朝向箭头、色带延伸）
3. 用**高度差**制造「看得见的落差」——目标平台更高更醒目

### 可提炼的设计手法（可直接对应到我们的项目）

#### 1. 落点必须有「站位提示」
传送的挑战不只是「到不了」，而是**「到了但站错位置」**——
所以需要一个明确标记告诉玩家「站这里」。
白色圆盘就是这个东西。

**→ 对应我们的项目**：`FireAtAnchor` 自动瞄准后，
球应该落在锚点的什么位置？目前是直接 `Attach(target)`，
可以加一个「落点朝向提示」——告诉玩家球会挂在哪、朝哪摆。

#### 2. 出发点与目标点都要标记
地面 L 形标记 = 出发点，黄色块 = 目标点。
**玩家不需要记住位置，靠画面就能读懂关卡。**

**→ 对应我们的项目**：我们的锚点虽然是黄色小球，
但**没有标明「下一个该去哪」**。跳跃时玩家只能看到一堆锚点，
不知道哪个才是当前该用的。这可能是「基础移动不太行」的一部分原因。

#### 3. 多个候选点让玩家「判断」而非「记忆」
画面里散布多个黄色块，说明关卡设计允许**多条解决路径**，
玩家靠判断选择，而不是背路线。

**→ 对应我们的项目**：`PickBestAnchor` 自动选点，
玩家不需要判断——这与设计手法的「让玩家判断」相反。
但这不一定是坏事（降低上手难度），只是取舍不同。
**关键是：自动选点必须有明确的视觉反馈**，让玩家知道「为什么选了这个」。

#### 4. 传送不能破坏物理连续性
传送是瞬移（位置直接改），但**速度是保留的**——
否则每次传送后都要重新加速，关卡节奏会断掉。

**→ 与我们的设计一致**：我们的冲刺也遵循「只加速不瞬移」，
防止破坏动量守恒。传送类的能力同样要遵守这条。
